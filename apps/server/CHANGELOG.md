## 4.17.1

### Patch Changes

- 984fa66: 前缀预热根治缓存命中率崩塌（远端实测 1000 万输入仅 30% 命中的根因修复）：

  - 根因（实测确认）：DeepSeek prefix cache 在请求完成后才落盘，并发到达的同前缀请求互相看不到对方的前缀单元——实测并发同前缀 3 请求全部 0% 命中、串行第 2 个起命中 95.3%、纯前缀预热后并发全部命中 94.2%。同章多块并发写作（输入大头）在旧调度下全部 miss。
  - 修复：调度器分组发射前，组内 ≥2 请求的同前缀家族先发 maxTokens=1 纯前缀轻量请求落盘，完成后再并发发射家族内全部请求（预热成本 = 一次前缀输入，换来家族内全量命中 L0-L2 共享段）；warmed 状态按前缀本体 hash 记忆（跨文档同 prefixKey 不误判）；预热失败自动降级为无预热并发，正式请求零阻塞。
  - 附带修复：证据渲染 omittedNote（含 per-call 统计计数）从证据段第 2 位移至尾部，避免其后 T0/T1/T2 证据大头在参数差异时整体错过前缀缓存。
  - 回退开关：DOCUMENT_PREFIX_WARMUP=0 关闭预热。
