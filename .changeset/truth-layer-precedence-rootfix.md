4.55.22 真值层三个独立缺陷根治（4.55.21 发布前拦截：现行口径实际判错）

**背景（必须记录的事实）**：4.55.21 的 changelog 声称「金额 157,166,591.34 元 / 工期 330 日历天 /
开工 10-10」，但用巢湖真实资料包（2,876 条证据）跑真值层实测，三项**同时判错**：
合同金额 = 4,000,000.00 元（暂列金额）、计划工期 = 365 日历天、开工日期 = 2026年8月31日（已被澄清掉的旧值）。
回归全绿却判错的原因：既有用例把值**作为 fact 直喂**裁决链，从未走 `extractLabeledAuthorityValues`
（带口径标签的原文抽取）——缺陷整条藏在未覆盖路径里。本版补齐该路径的用例，并根治三个独立缺陷。

**缺陷一：连接语正则缺非捕获组（`|` 优先级）**
`new RegExp(`${CONNECTORS}\\s*[:：]?\\s*(\\d+)…`)` 里后缀只作用于**最后一个**分支，其余分支以
「裸连接语」成功匹配且捕获组为 `null` → 「取变更后值」分支永不生效。
实测：「现变更修改为:330日历天」命中「变更修改为」而 `match[1]=null` → **330 静默丢失、365 胜出**。
根修：`(?:${CHANGE_CONNECTORS})`。

**缺陷二：口径标签与变更值相隔 >16 字时规则正则整体失配**
实测：「计划工期**于2026年08月05日**变更修改为330日历天」——标签后 16 字窗口够不到 330，候选为空。
根修：同句出现工期口径标签 + 变更连接语时，一律取**连接语之后**的值（距离无关）。

**缺陷三：组成性标签被当成总额（金额判错的直接原因）**
实测：「最高投标限价**暂列金额由**4000000.00元调整为7000000.00元」→ 4,000,000.00 元（暂列金额）
被抽成合同金额，并在时序裁决（7 号答疑号最大）里压过真正的总额 157,166,591.34 元（5 号答疑）。
根修：口径标签与数值之间出现「暂列/暂估/分部分项/单价/合价…」等组成性标签 → 判为组成部分，拒收。

**裁决链补强（同类问题一并根治）**
- **R1 生效值升格**：值级覆盖的生效值若未被带标签抽取/事实池捕获，原实现「候选被过滤空 → 回退全量」
  等于**放弃覆盖**；现由覆盖链**升格为候选**（来源取覆盖证据，优先级/时序同源）→ 工期由 R1 正确收敛。
- **R7 终止比较器全序化**：原实现取 `narrowed[0]`（数组序 = 事实池拼接序，与资料时序无关），
  实测开工日期在同源同优先级两候选间取到靠前者 = 被澄清掉的旧值。现按
  「澄清后值 > 后发布资料 > 载体优先级 > 更具体 > 稳定字典序」确定性收敛，**结果与输入顺序无关**。
- **澄清语境段落级判定**：澄清标记（现澄清为/现变更为/现调整为/作废…）落在**段落**上而非值文本上；
  提问段（编号/「问：」且含问号）重置语境——提问里复述的原值不再被误标为「后口径」。
- **值形态完整性**：带标签工期必须是「365日历天」而非裸「365」——裸数字会让覆盖表退化成
  `365 → 330日历天`，正文任意位置的 365 都被替换（含「1365」）。配套数值边界守卫。
- **R6 计数归一**：「2026年8月31日」与「2026年08月31日」是同一日期却各计一票 → 日期去前导零、金额归一。
- **跨资料包隔离**：裁决域收窄到**候选最多的资料包**，其余候选记入 `noiseRejected`（可审计）。
  实测：知识库同库并存 3 个项目（丰乐镇 90日历天 / 舒城 360日历天 / 巢湖 330日历天）时，
  无主体约束的裁决把 90日历天 判成「巢湖工期」。保守边界：存在裸文件名来源时不启用（不误删合法事实）。

**口径残留终检**：`caliberConsistencyIssues` 原只判「生效值是否落位」，正文同时出现生效值与旧值
（「总工期330日历天」+ 别处「365天」）会被判通过。新增**被取代值残留**判据（同族单位 + 数值边界，
含去单位的裸数字形态）；变更过程陈述（「原为365日历天…现澄清变更为330日历天」）豁免。

**回归**：全仓 341 文件 / 14,522 用例通过（新增 22 条针对性用例：三个缺陷各自的最小球、
巢湖多补疑难端到端、裁决顺序无关性、跨包隔离与保守边界、覆盖表边界守卫、残留终检）；typecheck 与 eslint 全绿。
