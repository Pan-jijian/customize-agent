## 二、逐轮根因与修复（全部机制化，无项目数值常量）

### 第一轮（83）：整章丢失掩盖了所有增益
- **根因**：第 1 章 34 个规划块只有 1 块（「主要施工内容」）密度失守，其余 33 块成稿却被**整体丢弃**
  → 终稿缺该章（33,570 字 / 目标 50,000；BOQ 落位 732/1387）。
  `.dbg/final-acceptance-record.md` 记录同类事故历史上已发生 8 次。
- **修复**：块失守改为**显式降级**——保留全部成功块、失守块不产出正文（不得用低质量兜底填充），
  产出 blocker 级 structure issue（点名失守块与失败原因）+ 阶段三档 `partial`（黄灯）；
  成功块为 0 仍照旧整章阻断；C7 超产接纳先判、不适用才降级。
- 同时修：口径终检只判**项目级口径**（读写同源）、事实冲突可比值取变更连接语之后的生效值。

### 第二轮（84）：合规维度被「回退」吃掉
- **根因 A（对账缺口 22 处）**：修复轮以「按《X》（编号）控制」形态补进章草稿并复检 29→1（阶段 success），
  但其后链尾 `stripDrawingPointerPhrases` 以**更宽**的判据把小句整句删掉（清洗判据宽于检测端）
  → markdown 丢引用、章草稿仍保留 →「报告说改了、产物里没有」。
- **根因 B（工期 365 三处）**：写侧「现行口径前置」把 365 就地改写进事实池，而 `writerEvidence` 与
  `allEvidence` **共享对象引用** → finalize 读侧重算时旧值已从候选集消失 → 变更链失配 → `superseded`
  变空 →「被取代值残留」闸拿不到输入而静默。
- **修复**：链尾重放 `replayTailStrippedBasisCitations`（判据只用清洗器本身，只回补"由标准名触发被误删"
  的小句；幂等）+ 应用指令加引用形态硬约束；变更链自证留存 + R2.5 澄清语境优先提前 + 残留分支不再被
  口径闸连带跳过；自伤豁免表补入**不合格品处置**动作（退场/拒收/退回…）。

### 第三轮（90）：事实一致性成为唯一短板
- 修 8 条：区间端点（`4~6米` 的上端点被当数量）、对象碰撞豁免（短名是长名后缀）、属性维度闸

## 四、结论

- **测量误报**（评分虚低的主因）已按机制系统性消除：口径终检 25→2、对账冲突 41→8→待测、
  强制模块 2/6→6/6、参数义务 54.1%→94.3%、无主数值缺口 9→3。
- **真实内容缺陷**已从「被误报淹没」变为**可枚举**：上表逐项可定位、可判真伪、可指派修复链。
- 综合分从 85（基线，且基线的事实一致性只有 36、口径终检 25 条误报）升到 **90**；
  第 4 轮验证第三轮修复的收敛效果。
- **通往 95 的剩余距离全部落在「事实完整与一致性」的算术峭壁上**：该维度要求冲突数 ≤1 才不失分，
  因此必须同时做到（a）文档本身零事实缺陷，（b）剩余检测器零误报。上表四项即为剩余全部障碍。
