# 4.57 篇幅预算体系重构方案

> 缘起：用户提出「把提示词里的字数要求去掉，改由模型根据招标文件与资料预估，再按重点难点划分」。
> 本文是该议题的完整方案。**结论先行：方向对，但不能去掉"刹车"，只能换刹车方式与刹车位置。**

---

## 一、实证基础（本仓已有 80+ 次直连实验 + 本会话 6 轮真实生成）

### 1.1 模型对字数的真实行为（`chapterGeneration.ts:272-279` 实验记录）

| # | 实验 | 结论 |
|---|---|---|
| ① | 最简指令「请写约 1500 字」 | 实测 **2434 字（1.62×）**，R 组 15 次调用 |
| ② | 目标语义（「约 N 字」/「篇幅目标 N」）全信号缩放 0.85 | **产出不变**——零咬合 |
| ③ | 上限语义（「不超过 N」） vs 目标语义 | **1.21× vs 1.64×**——上限是唯一有效信号 |
| ④ | 块级/点位/骨架全信号 ×0.75（V13，22 样本） | 产出落 0.81~1.25×，**82% 直通质检窗** |
| ⑤ | 全信号 ×0.70 | 100% 直通，但注释原话「**文档总量偏低**」 |

### 1.2 本会话 R0-a 补充证据（真实生成日志）

块目标 927 字时，同轮内实际产出跨 **697 ~ 1729 字（0.75× ~ 1.87×）**。
把欠产门线从 0.7× 提到 0.85× 并让末轮也设门 → **27/33、3/6 块成稿，丢弃 9 块**（失败原因全为篇幅）。

### 1.3 由此得到的三条硬结论

1. **绝对字数不是可执行的指令**——模型不认目标语义，只对上限语义有反应；
2. **块级是最差的字数控制粒度**——目标越小，相对波动越大；
3. **"丢内容"严格劣于"块偏短"**——收严判定必然导致正文丢弃，进而由修复链补写。

## 二、根因：字数在当前系统里同时承担了三个互相冲突的职责

| 职责 | 现状实现 | 为什么冲突 |
|---|---|---|
| **① 质量指令**（写够 = 写详细） | 块提示词给「目标字数」 | 模型只认上限（实验 ②③）→ 该职责**从未生效**，纯烧 token |
| **② 长度刹车**（别写太长） | 上限语义 + 末轮容差线 | **唯一有效的职责**，但用在块级（实验 1.2）→ 误伤最多 |
| **③ 分配依据**（章/块预算） | `allocateChapterTargets`（正则详略因子 × 小节数） | 分配依据本身不可靠（见下） |

**职责 ③ 的不可靠处**（`budget.ts:106-113`）：

```ts
function chapterDetailLevel(chapter) {
  const title = chapter.title + chapter.purpose;
  if (/方法|技术|质量|安全|进度|资源|保障|措施|部署|方案|流程|执行/u.test(title)) return 'detailed';
  if (/概况|结语|附录/u.test(title)) return 'brief';
  return 'standard';
}
```

于是「工程重难点及危大工程的保障体系与措施」只是**因为标题里有"措施"二字**拿到 detailed，
而「主要施工方法与技术措施」也拿到 detailed——两者重要性天差地别却同权重。

**并且总长度的来源同样脆弱**（`budget.ts:52 explicitLengthTargets`）：正则从提示词里抓
「不少于 X 万字」，抓不到就用模板 targetPages，再抓不到就用默认 1200 字/章。

> **这正是用户直觉指向的问题：字数不该由提示词拍脑袋给。** 判断成立。

## 三、设计总览：三个职责拆开，各用对的手段

```
① 质量指令  →  改为「资料落位义务」（可数、可验证）        【改造 5】
② 长度刹车  →  保留上限语义，位置从块级上移到章级          【改造 3/4】
③ 分配依据  →  长度锚改规模估算；章权重改三级回退          【改造 1/2】
                全程标注「来源 + 置信度」，降级不静默        【改造 6】
```

## 四、改造明细

### 改造 1：长度锚 —— 显式声明 → 项目规模估算（多级回退）

**现状**：`explicitLengthTargets`（提示词正则）→ 模板 `targetPages` → spec `minWords` → 默认 1200/章。

**改为四级回退，每级记录来源与置信度**：

| 级 | 来源 | 置信度 | 判据 |
|---|---|---|---|
| **T1** | 用户需求/提示词显式声明（「不少于 X 万字」/「X 页」） | **高** | 保持现有正则，用户说了算 |
| **T2** | 模板 `targetPages` / spec `minWords` | 中 | 保持现状 |
| **T3** | **项目规模估算**（新增） | 中 | 见下 |
| **T4** | 默认下限（1200/章） | 低 | 保持现状 |

**T3 估算器 `estimateDocumentScale()`（确定性、零 LLM）**：

输入全部是**已存在的可数量**，不新增数据源：

| 信号 | 现有来源 |
|---|---|
| 清单条目数 / 分部数 | `BillOfQuantitiesResult.entries` / `sections` |
| 图纸事实锁条数 | `drawingFactLock` |
| 台账要求条数（评分细目） | `tenderRequirements.entries` |
| 招标要求锚点数 | `collectRequirementAnchors`（已逐章计算） |
| 重难点条数 | 已有抽取 |
| 建筑面积 / 合同额 / 工期 | 真值层 `authoritativeValues` |

```
U（内容单元数） = Σ_章 ( 清单条目数×w₁ + 图纸事实数×w₂ + 评分细目数×w₃ + 要求锚点数×w₄ )
T（目标字数）   = U × 每单元经验字数 k
```

**k 与 w 用真实历史产出标定，不拍脑袋**——本仓已有大量真实产出可回归：

```
244,963 / 231,295 / 223,982 / 213,591 / 210,803 / 188,653 / … / 62,318（巢湖）
```

**为什么不让模型"预估字数"**：模型连"写 1500 字"都做不到（1.62× 偏差，实验 ①），
让它估总量只会引入一个**不可验证的数字**。模型没有标尺，系统有——清单 1387 条就是硬标尺。

---

### 改造 2：章权重 —— 正则 → 三级回退（L2 明确排除）

| 级 | 依据 | 可用性 | 置信度 |
|---|---|---|---|
| **L1** | 招标文件**项间分值/占比**（「确保安全文明生产的管理体系与措施 30%」） | 部分项目有 | **高** |
| **L2** | ~~评分档位（优/良/中/一般/差 → 100/90/80/70/60）~~ | —— | **明确排除** |
| **L3** | **可数结构线索**（改造 1 的同一批信号，按章归集） | **几乎总有** | 中 |
| **L4** | 现有正则详略因子（`chapterDetailLevel`） | 总有 | 低 |

**L2 为什么必须排除**：档位是「该项会被怎么评」，不是「该项占多少」。
把档位误读成权重，会把所有章算成一样重——比现在的正则还差。
（巢湖那张评分表恰好两种混在一起：「30%」是项间权重，「优/良/中/一般/差」是项内档位。
识别判据：**同一张表内多项带分值/百分比才算 L1；只有档位词一律走 L3。**）

**L1 缺失时的硬规则（零静默降级）**：
1. 用 L3 估算，但把 `weightSource: 'L3'` 记进文档元数据；
2. 章预算账里标注「本章预算为估算值」；
3. 评分/审计区分「招标明文分值」与「系统估算权重」，不混为一谈。

---

### 改造 3：提示词呈现 —— 删目标语义、留上限、加相对重点

**现状**（`chapterGeneration.ts:440`）：

```ts
`- 保留章节标题；本节正文总字数不超过 ${cap} 字（控制在 ${cap*0.85}~${cap} 字之间），超出即不合格。`
```

**改为**：

```
- 保留章节标题；本节正文不超过 {cap} 字，超出即不合格。
- 本章篇幅锚：约 {章预算} 字（{章名} 在本文档中属于{重点|一般|简述}章）。
- 本节须落位以下资料事实：{N 条}（逐条列出）——这是本节的「写够了」判据。
```

**要点**：
- **删除**所有「约 N 字」「目标 N 字」「建议 A~B 字」形式的目标语义（实验 ②：零咬合，纯浪费）；
- **保留并强化**上限语义（实验 ③：唯一有效）；
- **新增章级绝对锚**（章粒度波动远小于块粒度）+ **节级相对描述**（重点/一般/简述）；
- **节级不再给绝对下限**——下限职责交给「资料落位义务」（改造 5）。

**待实验标定**：实验 ①②③ 是在**块/小节级**做的，章级上限语义是否同样有效**尚无数据**，
需在改造 7 的灰度里补一组 A/B（章级上限 vs 章级无上限）。

---

### 改造 4：块级超产 —— 从失败判据改为章级压缩处理

**现状**（R0-a 后）：末轮 ≤1.4× 放行；**>1.4× 仍判块失败 → 丢内容**。

**改为**：块级**永不因篇幅判失败**。超产一律**接受该块**，由**章预算账 + 篇幅压缩轮**在章/文档级收敛。

**依据**：与 R0-a 同一结论——「丢内容严格劣于块偏长」。文档级膨胀由既有 `maxChars` 阻断线兜底
（`documentBudgetIssues`：>1.12× 为 error），章级漂移由章预算账告警。

---

### 改造 5：质量职责 —— 字数 → 资料落位率（可数、可验证）

这是本次方案**最重要的一条**：字数的"质量指令"职责从未生效，应由**可数的落位义务**接管。

**现状已有的落位判据**（保留）：
- 参数密度 ≥2 个/千字（`chapterGeneration.ts:138`）
- 必须落位清单参数 / 图纸事实锁 / 真值层口径
- `factReconciliation` 的「无据不写」

**新增（写作期反馈，替代"还差 X 字"）**：

```
本章绑定的 32 条资料事实中已落位 12 条；本章绑定的 7 条评分细目中已响应 3 条。
```

**为什么这个比字数好**：
1. **可数、可验证**——不依赖模型的计数能力；
2. **直接对应评标**——评分细目响应率就是得分点；
3. **不会诱导注水**——"再写 300 字"会让模型灌水，"再落位 3 条资料"不会。

**这块素材已经齐备**：`chapterFactNeeds` / `resolvedFactNeeds` / `requiredMissingNeeds`
（`stageChapterLoop.ts:510-512`）已在算，只是**没有作为写作期反馈下发**。

---

### 改造 6：度量 —— 来源与置信度入元数据，新旧并行

新增文档级元数据：

```ts
budgetProvenance: {
  targetSource: 'T1' | 'T2' | 'T3' | 'T4';   // 长度锚来源
  targetConfidence: 'high' | 'medium' | 'low';
  weightSource: 'L1' | 'L3' | 'L4';          // 章权重来源
  weightConfidence: 'high' | 'medium' | 'low';
  estimatedUnits: number;                     // T3 的内容单元数
}
```

- 评分报告区分「招标明文目标」与「系统估算目标」，**历史快照不回改**；
- 新旧口径并行一个版本，标注「口径变更」。

| 期 | 内容 | 风险 | 判据 |

1. 写作完成率 ≥95%（当前 ~94%）
2. **修复链净增字数占预算比 ≤5%**（当前 +66%）
3. 每次生成的红/黄阶段数 ≤2
4. 文档总量 ∈ [0.9, 1.15] × 目标

## 六、明确不做（防重走）

| 不做 | 原因 |
|---|---|
| 去掉上限语义（全部字数指令） | 实验 ③：上限是**唯一**有效信号；去掉 = 去掉唯一刹车，模型天然偏长 1.62× |
| 让 LLM 直接"预估总字数" | 模型无计数能力（实验 ①）；且产出不可验证的数字 |
| 把评分**档位**（优/良/中）当权重 | 档位是项内评分标准，不是项间权重；误读会使所有章等权 |
| 用"调阈值"处理块级篇幅 | 已被 R0-a 证伪：收严 → 丢内容 → 修复链补写 |
| 改动历史评分快照 | 口径变更必须可区分，否则历史无法比对 |
| 招标文件→章节结构通道 | 用户 2026-09-23 明确暂缓（见 `plan-4.56-complete.md` 第七节相关讨论） |

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| T3 估算偏差大 | 影子模式先跑；用历史 20+ 份真实产出回归标定 k 与 w；偏差 >25% 不启用 |
| L3 权重把某章算得过重 | 与 L4 正则结果对比，取"排序相关性"作为验收（不要求数值一致，要求排序一致） |
| 章级上限语义不咬合（无数据） | P4 专门做 A/B；不咬合则回退到"章预算仅作内部度量" |
| 提示词文案改动影响前缀缓存命中率 | 文案改动集中在校准段；对比改动前后缓存命中率 |
| 基线重置导致历史分数不可比 | 改造 6 元数据 + 新旧口径并行一个版本 |
| 资料落位率反馈增加提示词长度 | 只下发**未落位**条目（已落位的不重复下发），长度可控 |

## 八、与其它改造的关系

- **不依赖**招标文件→章节结构通道（已暂缓），可独立推进；
- **复用** `chapterBudgetLedger`（4.56 改造 2-b）作为章级度量的载体；
- **衔接** `改造 2-d 单一真相源`：本方案的 `budgetProvenance` 是其前置条件之一；
- **补充** R0-a：R0-a 解决了"篇幅不该是块级失败理由"，本方案解决"那什么该是"。
