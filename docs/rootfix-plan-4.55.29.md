## 0. 第一原则：口径来自输入，代码只持机制

**本方案不引入任何项目数值常量。** 所有口径都从下面三个来源解析：

| 来源 | 内容 | 现有机制 |
|---|---|---|
| ① 用户提示词 / 需求 | 字数目标、页数目标、编写要求 | `budget.ts:226` `buildDocumentBudget()` → `explicitLengthTargets(requirement)` / `explicitLengthTargets(promptTexts)`；支持 `targetChars` 与 `targetPages` 两种口径，`charsPerPage` 取自 template 的 `exportSettings` |
| ② 招标文件 | 评分因素与权重、编制要求（页数/排版）、建设规模、工期、金额 | 部分已有（`tenderRequirements.ts`、`factsModel.ts` 抽取）；**评分表权重解析与编制要求解析缺失**（见 §L5-C） |
| ③ 项目资料 | 工程量清单、图纸、答疑澄清 | `billFactLock.ts`、`drawingFactLock.ts`、`valueOverride.ts` |

**反面清单（上一版方案已全部移除）**：硬编码的「≤45,000 字」「13,500 / 13,500 / 18,000 字」「50 页上限」「按 30/30/40 配比」。这些都不是代码该持有的东西——字数由用户提示词给，页数限制由招标文件给，权重（若要用）由招标文件评分表解析。

## 3. 关键判据：分数缺口里约 70% 是测量误报，不是文档差

### 3.1 误报源①：`draft.facts` 33 字段错值填充（→ 25 条「口径不一致」→ 事实一致性 36 分）

```
占位文本被当成事实（4/33）：项目编号 / 计划工期 / 劳动力计划 / 工期关键节点
                            = 「未在资料中明确体现」

                  安全合规要求 = 风险控制要求
```
