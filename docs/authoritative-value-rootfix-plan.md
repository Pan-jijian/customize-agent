# 交付一致性根治方案 v3（值级覆盖 + 决定性裁决）——待审查

> 状态：**待审查（未动代码）**
> **v3 修正（按你的第三条意见）**：删除一切"待人工确认"逃生口。这是**全自动生成**产品——
> 不确定**不允许**变成标注、更不允许留空，必须由**规则自己决出唯一值**，并给出"依据哪条规则、哪份资料"。
>
> 三条约束的最终形态：
> ① 不留空 → 任何属性恒有值；
> ② 不预设字段 → 值级覆盖（被取代值→生效值），任何数据类型零改造；
> ③ **不人工介入** → **决定性裁决**：全序规则链逐步收敛，直到唯一值；每条裁决输出依据（规则 + 证据），
>    机器可读、可复核、可回归测试。

## 0. 四条原则

| 原则 | 含义 |
|---|---|
| **A 恒有值** | 交付物里不存在空值/待定/待确认；解析不到时按规则链决出 |
| **B 不预设字段** | 治理粒度是**值对**（被取代→生效），不是字段白名单；新出现的数据类型自动纳入 |
| **C 全自动裁决** | **决定性全序**：逐步收敛到唯一值；不允许"交人工"作为终止条件 |
| **D 单点真值 + 可溯源** | 全链只读真值层；每条裁决可回答"依据规则 R、资料 D 的哪一条" |

## 1. 值级覆盖 VLO（不变，v2 已定）

**抽取（句式族，零字段知识）**：
| 句式族 | 例（巢湖实锤 / 同类） |
|---|---|
| 变更连接语 | 「365日历天，现变更修改为:330日历天」；「合同估算价由 X 调整为 Y」 |
| 原现对举 | 「原 A，现 B」；「A（现变更为 B）」 |
| 澄清表行 | 「条款号/条款名称/编列内容」表逐行 |
| 答疑问答对 | 「问：…X… 答：…Y…」（问句值=被取代，答案值=生效） |
| 同实体跨文对照 | 同一实体在招标与答疑各出现一次（招标值=被取代） |
| **新增型** | 答疑**新增**内容（实锤：「新增第15项屋面板参考品牌…」）→ 不是覆盖，进要求池 |

**语境内核 scope**：每个值对带条款号/关键词/实体名，应用时限定语境，防同形值误伤。

## 2. 决定性裁决（v3 核心：取代"待人工确认"）

对每个属性，把候选值集按**全序规则链**逐步收敛，**必然终止于唯一值**：

```
候选值集（噪声剔除后）
  ↓ R1 变更链收敛：显式变更语式产出的"被取代值"出局
  ↓ R2 来源层级：答疑/补遗 > 招标澄清 > 招标正文 > 清单 > 图纸 > 企业经验
  ↓ R3 同层时序：资料发布时序（答疑编号/文件日期），后发布者胜
  ↓ R4 同文件条款序：条款号大者胜（同文件内后修订）
  ↓ R5 形态类型专属权威（由【值的形态】推断类型，不依赖字段名）
  ↓ R6 证据计数：同一值在资料中出现次数多者胜
  ↓ R7 安全侧规则（按形态类型定义，通用规则）：见下表
  → 唯一值
```

### R5 形态类型推断（关键：通用、可扩展、非字段白名单）

| 形态 | 类型 | 权威顺序 |
|---|---|---|
| 数字 + 工程单位（m/m²/m³/t/个/座…） | 工程量/尺寸/数量 | **清单 > 图纸 > 招标正文**（工程实体以清单图纸为准） |
| 强度/规格 token（C30、HRB400、DN200、40mm） | 材料规格 | **图纸 > 清单 > 招标正文** |
| 日期（YYYY年M月D日） | 时间 | 答疑 > 招标（含变更语式时按 VLO） |
| 金额（万元/元） | 造价 | 答疑（澄清）> 招标控制价口径；商务口径不得改写技术标（技术标零商务句） |
| 规范/标准编号（GB/JGJ/CJJ…） | 规范引用 | **合并全集**（不择一：多份标准并存是常态），去重后全部列入编制依据 |
| 其余文本（品牌/做法/描述） | 文本 | 答疑 > 招标；若为并列关系（"A、B 均可"）→ **合并表述**；若为替换关系 → 取生效值 |

*R5 的"类型"由值本身形态决定 —— 下一份答疑里出现任何新东西，都会被形态规则接住，无需改代码。*

### R7 兜底规则（最后一级；**不含任何"我们自行取舍"的方向选择**）

原则：**技术标对工期/标准等"招标方要求型"字段没有裁量权**——只能准确取到招标方的**最新要求值**，
不得为了让正文"更好看"而自行放宽或收紧（自行改动 = 不响应）。

| 类型 | 兜底取值 | 理由 |
|---|---|---|
| **工期/时间类** | **取招标方要求的生效值**：答疑澄清后值 > 招标要求值；并列候选取**与招标要求一致者**；连招标要求都取不到时取资料中出现次数最多者 | 工期唯一正解=招标方最新要求（如招标 365、答疑澄清 330 → 唯一正解 330）。**不存在"偏保守还是偏响应"的选择**——那是伪选择，任何自行放宽/收紧都是不响应 |
| 规范/标准类 | 合并全集（去重），不做取舍 | 多标准并存是常态 |
| 工程量/尺寸类 | 取清单/图纸值（法定实体依据） | 清单图纸为工程实体的权威载体 |
| 金额类 | 取招标控制价/答疑澄清值；且**技术标正文零商务句** | 造价口径属商务标 |
| 文本类 | 取答疑生效值；并列且非替换关系时**合并表述** | 评标按实质响应 |

**每条裁决输出**：`{ value, rule: 'R2', evidence: [资料路径 + 原文片段] }` → 进「口径账本」。
**无"待人工确认"分支**：规则链是**全序**（每一级都定义 tie-break），必然产出唯一值。

## 7. 落地顺序与验收

**顺序**：VLO 抽取 + 真值层**读侧**（只出账本，不改写作）→ 噪声闸前移 → 全链只读 → 一致性自检 → 参数绑定 → 残片与检测器收口。

**验收（巢湖 + 丰乐镇 真实 A/B）**：
1. **零空白**：报告中无空值；
2. **零人工分支**：任何属性都由规则链决出（账本可见 `rule`），全流程无"待人工确认"环节；
3. **口径单一**：任一属性在正文/表格/信息表只有一个口径；
4. **变更链完整**：365→330 可见（生效值/历史值/来源）；
5. **危大具体**：含本项目实际参数并与判定绑定；
6. **正文纯净度**：图签/OCR/答疑残片/清单口径词 0 处；
7. **一致性自检**构建期通过。

**边界**：不新增 LLM 判定维度（全确定性）；不新增依赖；不为分数放宽阈值；
**任何不确定都由规则决出**——这是全自动产品，规则必须穷尽情形。
