## 3. 统一尺设计（合尺）

### 3.1 设计原则

1. **一把尺**：只有一个分数来源；
2. **对账优先**：每个维度都必须能回答"依据是哪份资料的哪一条"；不可追溯的不计分；
3. **形态类不进分**：只做前置校验（不合格 → 确定性修复 → 仍不合格进清单），**不封顶、不降档**；
4. **靶线用"缺口清单"而非百分比**：对账型指标问"缺口是否有正当理由并逐条豁免"，不问"比率是否达标"——83.9% 是高是低永远说不清，**未落位的那 223 条有没有理由才是判据**；
5. **阻断 ≠ 拿不到文档**（沿用 4.50 口径）：任何不合格都不阻塞查看/导出，只决定状态与清单。

### 3.2 A 类 · 硬线（必须满足，否则不得标 completed）

| 硬线 | 判据 | 数据源（现成） |
|---|---|---|
| 数据溯源 | 正文数值**无主数值 = 0**（或逐条登记豁免） | `authorityAudit`（现：扫描 615 / 匹配 570 / 缺口 14） |
| 事实一致 | 同口径冲突 = 0、绑定冲突 = 0 | `factIntegrity`（现：冲突 10、绑定 3） |
| 编制依据双向对账 | 声明未用 = 0 且 引用未声明 = 0 | 现有（缺口 6/1） |
| **项目类型一致**（新） | 无与项目类型矛盾的用词/话术 | 新增，见 W1 |
| 要求响应 | 招标硬性要求锚点命中 = 100%（未命中须有"不适用"裁定） | `requirementAcceptanceIssues` + `requirementAssignments`（现：152/166） |
| 形态完整 | 无截断/空节/未闭合（**误判修准后**） | 结构检测器（先做 W3） |

### 3.3 B 类 · 覆盖率（缺口清单制）

对账每一类"资料 → 正文"的映射，**输出缺口明细而非百分比**：

| 项 | 判据 | 数据源 |
|---|---|---|
| 清单落位 | 每条未落位清单行须有豁免理由（分部小计/甲供/暂列/措施类…）；无理由者列入缺口 | `billPlacementAudit`（现 1164/1387，豁免 32 条分部小计） |
| 参数溯源 | 同上 | `parameterUsageAudit`（现 101/257） |
| 图纸事实引用 | 同上 | `drawingFactLock`（现 21/22） |
| 必备表与图 | 招标要求出的表逐项"有 / 等效替代 / 豁免" | 表执行 29/29 + 新增替代检查（W5） |
| 分阶段与人员量化 | 蓝图分阶段劳动力/机械/材料 → 正文引用 | 蓝图 `labor.byPhase` / `milestones` |

### 3.4 C 类 · 质量分（连续加权，仅作排序与横向比较）

| 维度 | 权重 | 依据 |
|---|---|---|
| 专业深度（章级靶线达标率） | 30% | `professionalDepthClassifier`（现 82，薄弱 3 章 6/12） |
| 要求响应充分度（响应条目的实质覆盖，非词面） | 25% | 要求实体响应 + 锚点 |
| 表述实质性（套话/句模/归因，**修准后**） | 20% | 现有三检（P3/P5 修好后） |
| 呈现质量（表完整/题注/替代完整性） | 15% | `tableScore` + 新增 |
| 篇幅与结构适配 | 10% | 现有 |

### 3.5 状态判定（替代现有"模板化封顶"）

```
硬线全过 且 覆盖率缺口 = 0 且 质量分 ≥ 靶线   → completed
否则                                        → completed_with_issues + 逐条复核清单
                                             （每条须含：依据资料 / 缺口 / 修复路径）
导出始终可用（与 4.50 一致）
```

## 5. 五个决策（我定的最优方案 + 理由）

| # | 决策 | **结论** | 理由 |
|---|---|---|---|
| **D1** | 模板化是否还封顶 | **取消封顶**；把"套话/句模/归因"修准后并入 C 类"表述实质性"维度（权重 20%） | 封顶是**单点否决**，把连续质量压成二值，且会掩盖其他维度的真实水平（巢湖即例：实质短板在数据锚定 64，却因一个失效闸门把总分压到 54）。**信号不该丢** → 降权并入，而非删除 |
| **D2** | 靶线怎么定 | 分三类：**硬线**（必须 100%，错就是错）、**覆盖率**（缺口清单 + 逐条豁免，不用百分比）、**质量分**（连续加权 + 靶线仅作排序） | 对账型指标问"比率是否达标"永远说不清（83.9% 算好还是差？）；**"未落位的那 223 条有没有正当理由"才是可判定的**，且天然可追溯到资料 |
| **D3** | 形态类不合格是否阻断交付 | **不阻断导出**（沿用 4.50），但**不得标 completed** → 状态置 `completed_with_issues` 并逐条进清单；仅硬线同样处理（不阻断导出） | 4.50 已确立"阻断 ≠ 拿不到文档"，本次不倒退；同时"不得标 completed"保证不合格不被掩盖。形态类在 W3 修准后残留的确属硬伤（截断/空节），必须让人看到 |
| **D4** | W1 改判后已生成文档 | **不自动重跑**；做三件事：①对既有文档跑一次**类型一致性审计**，标出错配清单；②提供"按新策略重新生成"入口（按需）；③新生成一律用新判据 | 历史文档是已交付物，自动重跑会覆盖；但**不能假装历史没问题** → 审计 + 按需重生成，把选择权交给使用者 |
| **D5** | 实施顺序 | **W1 → W4 → W3 → W2 → W5 → W7 → W6**（W1/W4 可并行；W3 必须早于 W2；W6 单独一轮） | 按**依赖**而非按风险排：W3 不先修准，W2 会把误判带进新尺；W1 是"内容性质就错了"，独立且最严重；W6 依赖 W2 定的"什么算章缺失"口径，放最后 |

## 6. 验收、回归与观测

1. **每个工作项都必须有真实数据 A/B**，不接受"单测过了就算"：以巢湖（产业园）+ 丰乐镇（乡村）两份真实资料为基准，逐项对照；
2. **自测不得中途打断**（本轮教训：中途 abort 会把修复轮中间态误判成缺陷）；
3. **评分构成必须可溯源**：新尺每个维度输出"缺口明细 + 依据资料"，可在文档记录页展开核查；
4. **新旧口径对照**：合尺后保留一版旧分对照表，便于判断口径变化带来的位移（不混入真实质量变化）；
5. **回归门禁**：全量单测 + tsc + eslint + 真实自测三件套，缺一不发版。

## 7. 明确不做（边界）

- **不改招标文件与清单的解析结果**（除 W1 的策略选型外）；
- **不为了让分好看而放宽任何阈值**——W3 修的是**误判**（把正常短名判残缺），不是把尺子调松；
- **不做批量自动重生成**（D4）；
- **不引入新的 LLM 评审维度**（成本与稳定性），新维度全部基于**已有确定性产物**（锁/审计/对账表）；
- 已否决的解析提速方向不再重复投入（P12）。

## 附录 B：口径陷阱（本轮踩过，防止重犯）

1. **中途 abort 不得用于结论**：修复轮中间值（深度缺口 1036、篇幅超 57%）会误导，须以终态为准；
2. **正则先做形状校验**：`grep -o` 截后缀（"9个自然村分组"→"9个自然村"）、`\\d` 转义失效（人数误报 0 处）、`# ` 匹配不到终稿 `## 第N章`；
3. **SQL 限定文件**：`like '%招标文件%'` 会跨项目混查（曾把舒城暗标标记当成丰乐镇的）；
4. **验证度量分辨率**：表头行通过而真实内容不通过 = 度量失效（供给面、归因闸门同型）；
5. **先看"主尺/从尺"自称口径**：`professionalScore` 自己写着"从属口径"，我曾拿它当结论。
