## 2. 逐项方案

### A. 真值层「值-属性错配」（P0，最高优先）

**证据（交付记录原文，共 ~25 条同型）**：

```
口径不一致：「材料投入计划」真值层生效值为「DN1000」（裁决 R7），正文未按该口径落位
口径不一致：「机械设备计划」真值层生效值为「DN1000」（裁决 R7），正文未按该口径落位
口径不一致：「检测仪器计划」真值层生效值为「接地系统测试（1#厂房安装工程）」（裁决 R1）
口径不一致：「技术参数精确参数」真值层生效值为「71807.64 平方米」（裁决 R7）
口径不一致：「劳动力计划」真值层生效值为「室外附属工程含混凝土管道铺设(人机配合下管)」（裁决 R1）
口径不一致：「质量控制点」真值层生效值为「设置在机动车道下的检查井铸铁井盖与支座之间粘贴10MM厚氯丁橡胶垫圈」（裁决 R5）
```

**根因**：属性名与值之间**没有形态校验**。真值层从原文滑窗取到一个"标签"（如「机械…计划」）和一个"值"（如附近的 `DN1000`），二者形态毫无关系也照收；裁决链 R1~R7 在此之上再选一个"生效值"，于是产出一个**语义上不可能落位**的口径。写手写不出「材料投入计划 = DN1000」，检测器就永久报「未按该口径落位」——**这 25 条不可能靠改写作或改修复轮消掉，只能在真值层消掉**。

**改动点**：

1. **值-标签形态相容闸**（新增，单点）：抽取值对时校验「标签词类型 ↔ 值形态」相容，不相容即拒收并记 `noiseRejected`（可审计）。相容表由值形态推断（沿用 R5 既有思路，不预设字段白名单）：
   - 计划/方案/措施/要求/制度/职责 类标签 → 值的形态必须是**成句文本**（含谓词、长度 ≥ 12 字），**不得是裸型号/裸数值**；
   - 强度/规格/型号 类标签 → 值必须是 spec token（`C\d+`／`DN\d+`／`HRB\d+`／`\d+×\d+` 等）；
   - 数量/工程量/面积 类标签 → 必须是「数值 + 单位」；
   - 名称/地点/单位 类标签 → 必须是人名/地名形态，且**不得含工程做法谓词**。
2. **属性名合法性**（同上，配套）：属性名必须是**名词短语标签**，且与值在原文中**同句/同段相邻**（现有滑窗距离需收紧）；属性名不得是正文里被切碎的词（如「技术参数精确参数」这种由两个标签拼接出来的键，本身就是缺陷信号 → 拒收）。
3. **不影响既有裁决**：本次只加"**入闸**"，不动 R1~R7 的裁决规则与顺序（4.55.22 刚把裁决链调到全序，不动它）。
4. **回归**：把上表 6 条原文作为**负样本用例**（断言不再产出这些值对）；同时以 4.55.22 的巢湖真值层正样本（金额 157,166,591.34／工期 330／开工 10-10）为**正样本**，断言不变。

**验收**：重跑巢湖，`caliber-consistency` 报出的「未按该口径落位」从 ~25 条降到 **≤3 条**（剩余须逐条给出正当口径）；交付阻断从 63 项降到 **≤25 项**。

**风险**：中。入闸过严会误杀合法文本型属性（如「编制依据 = 施工图纸、招标答疑及招标人的要求、相关规范」是成句文本，必须放过）。→ 相容表按"成句 vs 裸 token"二分即可，不做精细语义判定。

### B. 危大参数错值（P0，安全性）与 CAD 双写伪影（P0，上游根因）

#### B1 危大参数错值 —— 已定位到确切函数

**证据（真值层原文，决定性）**：

```
「基坑开挖深度」生效值 = 24m（图纸标注：搭设高度24m及以上的落地式钢管脚手架工程(包括采光井、电梯井脚手架)）
```

**这是把"脚手架搭设高度 24m"的**危大目录条文**当成了"本工程基坑开挖深度 24m"。**

**根因**（`factGovernance.ts:269-350 extractDrawingAnnotationFacts`）：深度取值逻辑是「命中标签行 → **本行多个数值取绝对值最大者** → 值域 `>=1 && <50`（`:287`）」。危险目录条文行同样含「开挖深度」字样，行内的 `24`（来自搭设高度）落在 1~50 值域 → 被当成基坑深度。已有 `DRAWING_ANNOTATION_DEPTH_COMPARISON_RE`（`:259`）排除"超过/以上/以下"比较式整行，但**本行的 24 不在比较式里**（"搭设高度24m及以上"是另一小句），故漏网。

**后果（严重）**：①「超危大工程判定缺失：资料基坑开挖深度 24m（≥5m）」告警基于错值；② 危大分级可能被判成"超危大"；③ 真值层另一处生效值为 `1.75m`（裁决 R1，图纸标注）→ **同一属性两个值**。

**改动点**：
1. **取值必须与"实体标注"同现**：深度值须与 `坑底标高|坡底线|基坑底标高` 类**实体标注标签同现**，或与「开挖深度」标签**直接相邻（≤8 字）**；仅"行内含开挖深度字样"不再成立（危大目录条文行由此出局）。
2. **值域收紧**：基坑深度实参合理域改为 `0.5 ~ 15m`（房建/市政常见），超域即拒收（24m 出局）。**注意**：超危大阈值为 5m，实参可能 >5m（如 8m 基坑），故上限不能压到 5m；15m 足够覆盖常规项目，且本条的真值层 1.75m 亦在域内。
3. **条文行排除**：行内含「及以上|以上的|超过\d|专项施工方案|专家论证|住建部令|第37号」且不含实体标注 → 整行不作为实参来源。
4. **同属性单值断言**：修复后「基坑开挖深度」在真值层**只能有一个生效值**；若多来源冲突，按既有 R 链裁决，并把来源差异记入账本。

**验收**：「基坑开挖深度」生效值 = `1.75m`（图纸实体标注）；危大判定使用 1.75m（<3m → 非危大）或按资料实情给出；「超危大工程判定缺失」告警消失；新增负样本用例锁死"搭设高度24m"不得被读成基坑深度。

#### B2 CAD 双写伪影 —— 本轮新发现的**上游根因**

**实测（本地 `kb.db` 直查，可复现）**：
- 该库 `kb_chunks` 共 8,395 块，其中 **dwg/dxf 块 1,169 块**；
- 抽样 400 块：**重复行占比 ≥50% 的 96 块（24%）**，20%~50% 的 49 块（12%）→ **约 36% 的 CAD 块存在成规模双写**；
- 含 `1:1001:100` 的块 **14 块**（上一版把"比例尺重复"当成独立问题，其实它只是双写的一个症状）；
- 决定性样本（2#3#门卫结构施工图 `dwg#3`，626 字）：

```
JL2JL2 1-11-1
e.换填地基承载力特征值不小于65KPa。e.换填地基承载力特征值不小于65KPa。
900875 1:1001:100
5：本工程基础下做100厚碎石垫层，100厚C15混凝土垫层。5：本工程基础下做100厚碎石垫层，100厚C15混凝土垫层。
```

**根因（已定位）**：`packages/knowledge/src/extraction/content-extractor.ts:41` `layoutCadAnnotations()` 把同一行内的标注**按 x 坐标拼接**（`:69-76` `joinRow`），**没有相邻重复折叠**。DXF 中同一标注存在两条实体（TEXT/ATTRIB/MTEXT 叠放，DWG→DXF 转换常见）时，输出即 `文本文本`。

**后果**：① CAD 文本噪声密度**翻倍**；② 比例尺变成 `1:1001:100`（上一版 #2(a)）；③ 字符预算被浪费一半（同一块只装一半有效信息）；④ 模型面对双写文本更易抓错值；⑤ 参数池里出现「条款号条款号条款名称条款名称编列内容编列内容」这类复写残片（见 C 组）。

**改动点**（上游单点，收益覆盖 #2(a)/#4/C 三处）：
1. `layoutCadAnnotations`：`joinRow` 拼接时，**相邻（x 距离 < wordGap）且文本完全相同**的标注只保留一条；整行聚类后，**相邻行文本完全相同**的去重。
2. `buildCadSemanticNodes`（`:902`）：作为第二道保险，对输出行做「相邻重复行折叠」。
3. **不做全文级去重**（会误杀图纸里真实重复的表格行/编号）——只做**相邻同文本**折叠，判据窄而确定。

**PDF 路径**：**与 DOCX 不同源**——PDF 走 `marked` 渲染 `<ol><li>`（`export.ts:1142-1146`），编号由浏览器 list 计数器生成，与 `numId` 无关；`enhanceTocHtml`（`:919-930`）只处理目录区。**结论：PDF 是否真有"编号全文延续"须实测确认**（本轮用户口径包含 PDF，但代码上无对应根因）→ **列入 §4 的实测项**，实测若确有问题再定修点；不为未证实的现象先动代码。

**验收**：同一 DOCX 内多张有序列表各自从 1 起；正文不出现「续号. 1.」形态；PDF 实测结论记录在案。
