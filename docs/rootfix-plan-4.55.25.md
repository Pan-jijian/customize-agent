## 1. 问题本质（统一模型）

**所有"写错"与"改错"都发生在值脱离了它的对象之后。**

| 资料原文（实测） | 自带结构 | 现在 | 后果 |
|---|---|---|---|
| 清单：`1．部位：D4 2．结合层厚度…30厚Ds M20 3．面层材料… 4．基层做法：涂1.5mm厚JS-Ⅱ型…` | 部位 + 逐项属性:值 | 抽成 `精确参数=1.5mm` | 正文 4 个槽位都写 1.5mm |
| 清单：`PHC400-AB95` ＋ `混凝土强度等级：C80` | 型号与等级分列 | `C\d{2,3}` 抠出 `C400` | 修复器把正确的 C80 **改**成非法 C400 |
| 图纸：`塘渣层计算弯沉值为3.41mm，压实标准见垫层压实度要求` | 弯沉值≠层厚 | "层名垫层+邻近mm"绑定 | 正文全部垫层厚度（含正确的 100mm）→ 3.41mm → 1.5mm |
| 图纸：`1.75m/s ，基坑深度 -1.7 米` | 属性:值相邻 | "本行最大数值" | 真值层基坑深度 = 流速 1.75m（危大判定被污染） |

**实测规模**：本轮 30 条确定性替换中，**≈12 条把正确的值改错**，可自证正确的 **0 条**（真正改对的 5 条权威均来自显式声明）。

## 2. 根治设计

### 2.1 绑定层（BoundFact）：唯一合法来源 = 原文共现锚点

```
BoundFact = { object, attribute, value, unit, shape, source{file,原文片段,offset}, binding:'anchor' }
```

**三类锚点形态**（资料自带，不需要猜）：

| 锚点 | 例（实测） |
|---|---|
| **清单结构化子项** | 「1．部位：D4，有水房间」→ 其后各子项归该对象 |
| **表格行首/列头** | 清单行「墙面涂膜防水 … \| 4145.740 \| m2」→ 对象=该行条目名 |
| **说明句主语** | 「本工程**门卫**地上建筑面积 241.71 平方米」→ 对象=门卫 |

**二态穷尽**（无中间态）：

| 判定 | 处置 |
|---|---|
| 出现位置**有锚点** | **必须抽到**。抽不到 = **抽取器缺陷** → 构建期报出 + 计入「**解析覆盖率**」（目标 **100%**，逐条给原文位置），按 bug 清零 |
| 出现位置**无锚点** | 它不是"值"，是**残片** → 出局（噪声闸） |

> **实测**：池中显示"无对象"的 132 条（36.7%），抽样 5/5 锚点**都在原文里**——所以"抽不到"从来不是值的属性，而是抽取器没读对。
> **为什么不"值反查对象"**：值→对象是重度多对多（`C15` 出现在 1,089 个资料块、`100mm` 110 个、`1.5mm` 82 个）——反查要么恒多义（等于没做），要么在碰巧唯一时**凭空造出资料没给的绑定**，把"猜"包装成"验证过的权威"。

### 2.2 唯一铁律与归属域

> **铁律：`(对象, 属性)` 恒唯一**（变更链除外：显式变更语式产生新旧值对，生效值唯一，VLO 已有）。

| 对象粒度 | 例 | 表现 |
|---|---|---|
| 项目主体 | 工期、金额、开工日期、建设规模 | 表现为"单值" |
| 工程对象 | 垫层厚度、强度等级、管径、型号、配比、做法 | 表现为"多值"，但**每个对象各自唯一** |
| 规范/通用 | 规范号、阈值、龄期、频次、留置组数 | **不是项目实参**：可用于定性表述，禁止写成项目具体值、禁止当权威改写 |

**同一 `(对象,属性)` 出现多值 = 缺陷信号**（误归 / 抽取不全）→ **定位并报出，不裁决、不选值**。

### 2.3 写作注入：对象化 + 按章/按节分配

```
【本章对象参数清单（逐对象写实；值不得跨对象借用；同一属性在不同对象下各有其值，并列合规）】
· 基础碎石垫层（部位：基础）｜厚度=100mm｜材料=C15混凝土｜做法=分层摊铺、碾压密实
· 地坪垫层（部位：1#厂房地坪）｜厚度=300mm
· 块料地面 / D4（有水房间）｜结合层厚度=30厚Ds M20｜面层材料=防滑地砖600×600×10｜基层做法=涂1.5mm厚JS-Ⅱ型…
```

- 对象→章、对象→小节：复用 `chapterDutyDeclaration`/`plannedSectionPlacement` 匹配通道（不另造）。
- **分配不上 → 该对象不进正文**（宁缺毋假），进"分配缺口"观测项。
- 红线：不得写清单外的值；不得跨对象借用；**多对象多值并列合规，禁止"统一"**。
- 工艺/方法类同样绑定：`(对象, 做法, 文本)`（清单「基层做法／施工方法」子项、图纸设计说明做法句）。

### 2.4 权威自证（构建期四校验 + 运行期回读）

| 校验 | 内容 | 不通过 |
|---|---|---|
| ① 来源可溯 | 能回指 资料文件+原文片段+偏移 | 剔除 |
| ② 形态合法 | **单点值域闸**：强度等级 C15~C80；层厚 0.5~1000mm；配比分母 ≤100；管径 `DN\d+`；钢筋 `HRB/HPB\d{3}`；型号 token 不得字母紧邻（`PHC400`≠`C400`）；数值不得来自"偏差/弯沉/压实度/间距/标高"等异义槽 | 剔除并记 `noiseRejected` |
| ③ 属性自洽 | 属性名与值形态相容（文本型属性不得取裸型号值；拼接属性名非法；规格属性不得取长句） | 剔除 |
| ③b 三者共现 | `(对象,属性,值)` 必须原文共现 | 剔除（消掉 A 组 25 条误归） |
| ④ 规划自检 | ①每个 `(对象,属性)` 值唯一；②项目主体级多值 → 误归，定位剔除；③工程对象级同一对多值 → 报"未定"，不选值；④object 非空、非拼接、非残片 | **构建期报错**（宁停不猜） |

**运行期回读**：正文中每个对象的值必须 ∈ 该对象权威集合；越界才报「越界值」。

### 2.5 改写与报告口径

```
权威四校验通过？
 ├─ 通过 → 确定性改写该对象处的越界值 → 改完回读（同源检测器必须清零）
 │          → 报告：「已按 <资料名·原文片段> 将 <对象> 的 <属性> 由 X 改为 Y」
 └─ 不通过 → 既不报、也不改（仅进 diagnostics 观测指标，不进人工清单、不阻断）
```

## 3. 表格单元格实值化（新增专项）

**口径**：表格是**数据载体**，每个单元格必须是**实际内容**——不得是套话、指向、占位符、凑数文本。

**判据（任一成立即"实"）**：含数值+单位（`30厚`/`C15`/`DN100`/`2台`/`353人`）；含具体名物（`防滑地砖`/`塔式起重机`/`ALC板`）；工序链或做法（含 `→` 或施工动词）；闭环要素（岗位+频次+动作）。

**判据（任一命中即"虚"，必须为 0）**：
| 类型 | 例 |
|---|---|
| 指向型 | 「按设计图纸」「详见前述」「以…为准」 |
| 套话 | 「按实配置」「满足规范要求」「确保合格」 |
| 占位符 | `—`／`——`／`/`／`待定`／`待补`／`无数据`／`若干`／`N/A` |
| **凑数** | 单元格文本与**表头同名**、或与同列其它单元格**高度雷同（>80%）** |
| 单字空话 | 单/双字且非合法枚举值 |

**生成侧根治**：某列/某行无数据时，**不出该表**（或删该行），**禁止用「—」或套话填充**（宁缺毋假）。
**检测侧**：`hollow-table-cell` / `table-quality` / `formal-placeholder` 三处判据**合并为单源函数**（一条真值，检测=修复同源）。
**修复侧**：能自证（该单元格有绑定权威值）→ 填实；不能自证 → **该表不出**。

**实测基线**：本轮交付物 191 个数据行值列单元格中，套话/指向 **2（1.0%）**、占位 **0**、其余为实值或合法名物 → **目标：套话/指向/占位/凑数 全部归零**。

## 4. 正文零图（口径收紧）

**新口径**：正文**只有表**——**不再出现任何图题、图号、图件、图片**。原文里"要求出图"的条目，一律按**数据表**落实。

| 项 | 处置 |
|---|---|
| 图题/图号（`图1-1`…`图2-1`） | **不产生、不保留、不归一**——`normalizeFigureNumbering` 整体删除 |
| 图件（SVG）生成 | `documentFigures.ts` **整文件删除**（`buildScheduleGanttSvg`/`buildScheduleNetworkSvg`/`buildOrgChartSvg`/`buildFigureForName`） |
| 图件注入 | `figureImageResolver`、`ensureFigurePlaceholders` 的 `figureImage` 分支、`documentFigures` 相关的 `SubstituteTable`/图片引用注入——**全部删除** |
| 要求侧"出图" | 图类要求 → 转为**数据表要求**（沿用 `figureSubstituteTables` 的表构造，重构为"表计划"入口） |
| 导出侧图片路径 | `inlineLocalImages`、DOCX 图片光栅化、`word/media`、图片 rels/content-types —— **删除**（无图可导） |
| 机构图层级数据 | `ORG_CHART_HIERARCHY` 保留（机构替代表要用）——迁到表模块，随 `documentFigures.ts` 一起删除干净 |
| **保留（最小化）** | 暗标/禁图**守卫**（防写手插图：`![…]`/`<img>`/占位括号语）——它不是"出图"逻辑，是防线 |

**验收**：正文 `![` = 0、`图\d+-\d+` = 0、`fig-*.svg` 引用 = 0。

## 5. 旧逻辑清理（删除优先，不留兼容与兜底）

**原则**：删除，而不是加开关；不做"兼容分支"；不留"兜底路径"；对应测试**同步删除或改写为守卫**（断言"不该存在"）。

| 类别 | 删除对象 |
|---|---|
| 图件/图片 | 上一节全部；并删除 `documentFigures.ts` 及其测试、图件相关的快照/边界用例 |
| 图件开关 | 本轮曾引入的 `BODY_FIGURE_OUTPUT_ENABLED` 一律不要（图已彻底取消，不需要开关） |
| 参数注入旧格式 | `renderChapterParameterLines` 的扁平 `- 键（字段名）：值` 形态**整体替换**为对象化形态，不留双格式 |
| 提取型权威改写 | 结构层厚度/配比、跨节规格标号、表格唯一值归一、名称-数值绑定、清单锁值 —— 按 §2.5 改为"**四校验通过才改写**"，不通过的路径**删除**（不留"回滚/复检后再改"的旧分支） |
| 兜底分支 | 与本次口径冲突的"为兼容而保留"的分支（如"未传替代表回调时保持原行为"这类向后兼容路径）——删 |
| 死代码 | 任何因本次删除而失去调用方的导出/常量/检测器（如 `figure-substitute-table` 检测器、`figureCoverage`）——同步清理注册表与测试 |

## 7. 风险与不做

**风险**
1. 参数/表注入量可能下降（宁缺毋假）→ 相关评分指标口径需**同步调整**（改口径，不放宽阈值）。
2. 解析覆盖率短期达不到 100% → 缺口**可量化、可逐条清零**（这是推进方式，不是容忍）。
3. 删除量较大（图件 + 兜底分支）→ **分阶段删、每阶段跑全量测试**，不一次性大爆炸。

**明确不做**
- 不做"值反查/事后补绑"；不做"多值归一"；不用"提取到的唯一值"当权威。
- 不为兼容保留旧分支；不加开关；不留兜底路径。
- 不放宽任何阈值让指标好看。
