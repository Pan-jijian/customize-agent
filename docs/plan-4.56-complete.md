### 6.2 新发现（下批修复项）

**N-1（真实缺陷·潜在）异常路径被误报为「块质检未达标」** — `chapterGeneration.ts:1908` 的 `catch` 只写
`diagnostics.llm.lastError`（随后被下一块覆盖），`blockFailureKinds` / `blockLastAttempts` 保持 undefined，
章级记录于是走 `blockFailureReasonText` 的不透明兜底「块质检未达标（无类别与反馈记录）」。

- **三重损失**：① 归因错误（实为模型调用/解析/中止异常，与质检无关）；② `lastAttempt` 丢失 → C7

  潜在缺陷；但同一路径在真实网络/限流/解析失败时必然复现。
- **修法**：`blockFailureKinds` 增加 `'exception'` / `'aborted'` 两态，`catch` 内登记错误短句；
  `BLOCK_FAILURE_KIND_LABELS` 补 `exception: '生成异常（模型调用/解析失败）'`、`aborted: '用户中止'`；
  `blockFailureReasonText` 优先输出异常短句。**中止不计入质检类 blocker**。

**N-2（诊断缺陷）块质检日志不打印篇幅判据** — `[gen][block-qc] 块质检不达标` 行打印了缺标题/重复/

`篇幅 ${chars}/${targetWords}（欠产线 <${underProduceLine}，超产线 >${effectiveOverLine}）`。

## 七、远端用户「章节阻断 4/7」根因（4.56.3，优先级高于质量分）

**用户原话转述**：远端用户用**别的项目**生成，拿到的是

```
针对工程项目整体理解       依赖蓝图权威 [schedule]，蓝图校验项「0. 清单源可用性、1. Schema 校验」未通过 → 章节阻断：1/7
确保工期与质量的保障体系与措施 依赖蓝图权威 [schedule]，…                                    → 章节阻断：4/7
详情：「数值密集型章所需蓝图权威不可用时禁止无权威成稿」「请检查清单解析与蓝图构建诊断后重试」
```

**性质**：这不是质量问题，是**生成流程不可用**——7 章里 4 章不产出，且提示只有「重试」。

### 7.1 因果链（三段独立缺陷叠加）

| # | 缺陷 | 位置 | 后果 |
|---|---|---|---|
| N-4a | 权威需求判定**过触发**：正则兜底 `/进度计划\|进度\|工期/` 与 `/资源配置\|资源\|机械\|设备\|机具/` 命中**裸关键词**；语义锚点又把「施工部署/总体部署」并入 schedule 组 | `chapterIntentClassifier.ts:30-32`、`validate.ts` | 模板里绝大多数章标题都含「工期/设备/资源」→ 全被判数值密集章 |
| N-4b | **阻断判据 = 注入判据**：只要该权威不可用就**整章不产出** | `stageChapterLoop.ts:116`、`validate.ts:220` | 清单不可用 ⇒ 一次性毁掉 4/7 章 |
| N-5 | 精确诊断**无人消费**：`resolveBillOfQuantities` 已产出「未识别到清单文件／索引不存在／解析出 0 条目／仅封面类结构性文件」四类原因，写进 `diagnostics.warnings` 后**没有任何读取点** | `integratedBlueprint.ts:76` → `stageChapterLoop.ts` 阻断 stage | 用户只看到「请重试」，重试永不生效且无从定位 |

### 7.2 修复（4.56.3，均已落地+单测锁定）

- **N-4b（核心）**：把「该注入什么」与「什么必须阻断」**拆成两个判据**。
  - 注入判据 `chapterBlueprintAuthoritiesNeeded` **原封不动**（语义+正则 union，不缩小任何已注入数据）；
  - 新增**阻断判据的计划形态门** `isBlueprintPlanShapedChapter`：仅当标题含
    `计划/安排/规划/配置/部署/投入/需求/用量/数量/工程量/清单/表` 时才参与阻断。
  - 理由：`BlueprintAuthorityId` 的语义是「**由清单推导的计划性数值**」，只有交付物本身就是这些数值的章
    （进度计划/劳动力计划/资源配置计划/机械设备表）缺权威才必须阻断。而「工期保证措施」里的工期天数
    属**项目级口径**（真值层合同工期通道），不是蓝图推导值——阻断它不提升数值可信度，只毁文档。
- **N-4c（前提）**：「不阻断」必须配「不编数」。新增 `noBlueprintAuthorityConstraint`，
  在「原口径属蓝图权威章 **且** 未注入章切片」时注入写作 `roleContext`：
  **不得输出**里程碑日期／各阶段工期天数／总工期天数／劳动力峰值／机械台数／资源用量，
  不得用「约/左右」变通；合同工期与开竣工日期**照抄真值层**，不得自行推导。
- **N-5**：阻断 stage 的 `details` 携带清单侧诊断（按 /清单|知识库索引/ 过滤 `diagnostics.warnings`，最多 3 条），
  并给出分流指引（补资料/重建索引 vs. 确认模板资料需求中清单是否为必需项）。

### 7.3 判据

- 远端同类项目：`章节阻断` 应为 **0**；若清单确实缺失，仅**计划形态章**阻断，且消息带具体原因。
- 回归：`blueprintAuthority.test.ts` 30 项（含用户实测标题回放 + 真实计划章仍阻断 + 注入判据不收窄 +
  N-4c 约束已接线 + N-5 四类诊断词与消费点齐备）。
