## 三、元根因 M0：判据的「发现地」与「产生地」分离

### 3.1 证据

把 30 条阻断按「最早在哪一阶段被发现」归类：

| 最早发现阶段 | 条数 | 占比 |
|---|---|---|
| **终检 / 修复链之后** | **29** | **96.7%** |
| 写作期已阻止 | 1 | 3.3% |

**几乎 100% 的问题是"终检才发现"，而不是"写作期不产出"。**

### 3.2 这解释了用户从会话一开始就指出的两个现象

> *"我们写作的时候，生成的预算内容是不达标的，大部分内容是在后续修复链过程中进行补充的"*

修复链的净效果是**追加**而非改写：**净增字数 +66%**。追加带来两个次生缺陷，且都在本轮的阻断里：

- **段落近似重复 / 句式模板复读**（E 族）——追加的段落与原文重述同一批对象；
- **口径漂移**——追加时按当时的上下文理解写，与原文口径不一致。

### 3.3 为什么"打补丁"是必然的

现有架构里：

- **写作期**只受**提示词**约束（软）；
- **所有硬判据**（结构/要素/数值/要求）都在**终检**（硬）。

于是每发现一个新缺陷形态，只能**再加一个检测器 + 再加一条修复规则**——这就是"打补丁"的成因。
本项目已有 `detectorCallSite` 一致性门（检测器与注册点双向一致），但**没有**"检测器 ↔ 写作期约束"
的一致性门，所以"检测器只增不减、写作期约束不增"是**结构性的**，不是纪律问题。

## 四、根治框架：判据三态 + 写作期约束覆盖率门

### 4.1 判据三态（每条 error 级检测器必须落在其中一态）

| 态 | 含义 | 要求 |
|---|---|---|
| **① 写作期可约束** | 该判据能在写作提示词/任务卡里表达 | **必须**提供写作期约束（否则检测器不予注册） |
| **② 写作期不可约束、可自检** | 无法在提示词里表达，但能在块成稿后**当场检查并补写** | 必须接线到块级自检通道 |
| **③ 只能终检** | 依赖跨章/全文信息（如跨章一致性、近重复） | 必须**显式声明理由**，并登记到豁免表（双向一致，同 `detectorCallSite` 门同款纪律） |

### 4.2 新增门：**写作期约束覆盖率**（这是"根治"不退化的机制保证）

```ts
// 每条 error 级检测器的注册项新增必填字段
writingTimeDisposition:
  | { kind: 'constraint'; channel: '块任务卡' | '章约束' | '全局约束' }
  | { kind: 'self-check';  stage: '块成稿后' | '章成稿后' }
  | { kind: 'terminal-only'; reason: string }
```

CI 门：**新增 error 级检测器未声明 `writingTimeDisposition` → 红**；
`terminal-only` 必须有非空 reason，且计数纳入硬指标（目标：`terminal-only` 占比逐版本下降）。

**没有这个门，本方案就是又一轮补丁。**

## 五、分族根治方案

### R1 结构完整性（A 族，11 条）

**根因**：`plannedStructure` 规划了小节（H4），但**写作期没有"每个规划标题必须产出正文"的机械保证**。
块成稿返回后标题在、正文空 → 直到终检才发现（空小节 ×3、未落位 ×15、标题残缺 ×2 同源）。

**根治**：
1. **块成稿后的标题-正文对齐自检**（新增）：对每个规划 H4，检查其后是否有 ≥N 字正文；
   缺失 → **当场走续写通道**（复用 R0-b 的 `continueUnderProducedBlock`）。
   - 现有 `alignSimilarHeadingsToPlan` / `cleanStructureDefects` 是**规范化**，不是**缺正文检测**——这是缺口。
2. **章成稿后的标题完整性自检**：规划小节清单 ↔ 实际 H3/H4 清单双向对账，缺失即补。
3. **句尾截断**并入同通道：段落结尾无终止标点 → 当场续写收尾。
4. **表格题注**：表计划（`planned.tables` 已有表名+表头字段）在写作期就是已知的 → 题注编号
   应在**渲染时机械生成**，不应依赖模型（现在靠模型自觉，所以缺 ×3）。

### R2 内容要素与深度（B 族前 6 条）

**根因**：`sectionStructureIssue`（工作包三要素：作业对象与工程量 / 工序顺序 / 施工方法 / 工艺参数）
**只在检测侧**，写作侧只在**首轮**有反馈，末轮无 → 终检。

**根治**：把三要素判据**编译进块的写作任务卡**（`taskCardPrompt` 已有槽位）：

```
本节必须包含：① 作业对象与工程量（引清单条目） ② 工序顺序（用"先…再…随后…"以外的表达，
避免模板复读） ③ 施工方法（≥4 个工艺参数：mm/MPa/间距/偏差/试验压力）
```

并在块自检里**逐要素对照**，缺哪条补哪条（而不是整块重写）。

### R3 数值来源（B 族后 4 条）

**根因**：`factReconciliation` 的「无据不写」是终检；写作期只有**数量型**约束（参数密度 ≥2/千字），
没有**来源型**约束。于是：未溯源数值 ×N、无主数值、危大只抄规范阈值。

**根治**：写作任务卡**逐条列出本节的权威值清单**（现成件：`renderBlueprintMustCiteValues`、
真值层约束块、`billFactLock`、`drawingFactLock`），并加一条硬约束：

> 本节出现的每一个数值必须来自上方清单；**不得出现清单外的数值**。
> 危大分级必须写「本项目实际参数 + 判定阈值对照 + 结论」，禁止只抄规范阈值。

### R4 招标要求响应（C 族 + D 族的"被取代形态残留"）

**根因**：要求锚点**已逐章下发**（`chapterRequirementContext`），但写作期**没有锚点落位自检**。
答疑修正的"被取代形态"同理——账本已下发，但写作期不检查是否误用了旧形态。

**根治**：块自检通道里增加两个逐条检查：
- **要求锚点逐条命中**（复用 `requirementAnchorCoverage`，判据单源）→ 未命中且属本块 → 当场补写；
- **被取代形态逐条排除**（复用 `residueAsCurrent`）→ 命中即当场改写为修正后形态。

> 注：`23S516` 这类**图集号**此前判为"真未落位"，但它们属于**引用型**内容——
> 正文按图集做法写、不逐字复现图集号是合规的。故本项同时要给引用型锚点**豁免通道**
> （判据：`isDocumentReferenceTerm` 已有同款过滤，扩展到图集号/规范号）。

### R5 事实一致性（D 族，4 条）

| 条 | 根治 |
|---|---|
| 计划工期：`符合…第1.3.2项规定` 当值 | **合规引用句过滤**：`/^符合.*第[\d.]+项?(规定|要求)$/` 类形态不是取值。**同时必须解决"plain 混入打掉槽位分桶"**——分桶应改为「可按形态判定的值分桶，plain 值单独成组」，而不是"含 plain 就整体放弃分桶" |
| 建设地点：`安徽巢湖经开区` | **不做通用规则**（已判定无安全规则）。改为**降级为 warning**并附说明（省/市前缀形态差异），交由人工确认——它是**粒度差异不是冲突** |
| 同一参数多口径：对象名截断 | **对象名抽取修复**：`"25C)厚与细粒式改性沥"` 是定宽窗口截断产物。需按标点/括号边界收拢，并对两个残片做**包含关系判定**（一个是否是另一个的截断） |
| 被取代形态残留 | 见 R4 |

### R6 表达风格（E 族，2 条）

**根因**：各块**并发生成**，互相不知道对方写了什么；跨块去重只在终检。

**根治**（两选一，需实测选型）：
- **方案 a（轻）**：章内块**顺序生成**（牺牲并发），每块注入"本章已完成块的要点摘要"；
- **方案 b（重）**：两阶段——先各块出**要点骨架**（短），再做章级去重，然后各块按去重后的骨架展开正文。

建议先做 **a** 的**部分版**：仅对**同章**做"已完成后块的 H4 标题 + 关键对象清单"注入（不是全文），
成本低、能挡住大部分重述。

### R7 篇幅预算体系

见 `docs/plan-4.57-length-budget.md`（独立分册，P0~P4）。

### R8 修复链本身应当"改写"而非"追加"

**根因**：修复链净增字数 **+66%**——它在**补写**，而不是**改写**。补写正是 E 族重复与 D 族漂移的来源。

**根治**：
1. 修复轮**分别统计"新增字数"与"改写字数"**，把「新增占比」作为硬指标（目标 ≤5%）；
2. 修复动作优先级：**先尝试等量改写**（在原文对应位置替换），改写不可行才允许追加；
3. 追加必须携带**去重前置检查**（与 R6 共用判据）。

## 八、明确不做（防重走）

| 不做 | 原因 |
|---|---|
| 继续用"加检测器 + 加修复规则"处理新缺陷形态 | 这正是 96.7% 终检占比的成因；P0 门就是为拦住它 |
| 为 `安徽巢湖经开区` 写省市前缀合并规则 | 需地理知识，超出形态判据；误合并会把两个不同地点判成一个（比误报更危险） |
| 把"含 plain 就放弃分桶"保留 | 一个无关的 plain 值就能打掉整个分桶——本轮 `符合…规定` 正是如此 |
| 让模型"预估字数" | 见 4.57：模型无计数能力（1.62× 偏差） |
| 把评分档位当权重 | 见 4.57：档位是项内标准，不是项间权重 |
| 招标文件 → 章节结构通道 | 用户 2026-09-23 明确暂缓 |
| 用"扩空话词表"治废话 | 实测词表法命中 17 次/68113 字，**显著低估**；真正的缺口是**判定粒度**（整句 vs 短语）与**原型覆盖**（口号体 vs 条款体），扩表治不了 |
| 用"套话句占比"作为废话的唯一度量 | 它会漏掉"句中有实质内容、只有一处短语是套话"的形态；必须配段落级人工抽样 |
| 让模型自己写题注编号 | 双题注 `表1-34-1`/`表1-3` 与 4 张缺题注都由此而来；编号是机械信息，应由渲染层生成 |

## 九、风险与缓解

| 风险 | 缓解 |

### 11.3 为什么现有三层机制没拦住（精确缺口）

套话治理**三层齐备**：
1. **写作期约束**：`taskCardPrompt` 第 3 条「不得写成"结合实际、按规范执行"的泛化空话」；
2. **块质检**：`scanBlockTemplating` —— 套话句占比 >10% 阻断（与终检 `fillerDensityReport` 同源）；
3. **二轮定向反馈**：携带命中句原文，要求改写为「责任岗位 + 执行动作 + 量化标准 + 检查频次 + 整改时限」。

判据是 `judgeFillerSentences`：**14 条口号体语义原型** × **整句** cosine ≥ **0.80**。

**两个精确缺口（机制层原因，非纪律问题）**：

| 缺口 | 机制 | 实例 |
|---|---|---|
| **短语级套话被实质内容稀释** | 判定**整句级**且阈值 0.80；套话嵌在实质句中时，整句 embedding 由主体内容主导 → cosine 不足 | 行90 该句主题是"垫层与级配碎石验收"，"精心组织施工"只占一个短语 |
