## 0. 一页摘要

**问题本质（一句话）**：所有"写错"与"改错"都发生在**值脱离了它的对象**之后。

**方案主线（一句话）**：把「(对象, 属性, 值) @ 来源」这一**结构化绑定**从资料一路保真到写作与校验，
而不是在**扁平值**上做任何补救；**权威值必须可自证**——能自证的才改写（改完回读验证），不能自证的不报不改。

**唯一性铁律 + 归属域四分类**（混在一起是当前一切矛盾的根源）：

**唯一铁律（只有一条）**：**`(对象, 属性)` 恒唯一**——同一个对象的同一个属性只能有一个值
（变更链除外：由显式变更语式产生新旧值对，生效值唯一，已有 VLO 机制处理）。

单值型/多值型**不是属性名的固有分类**，而是**对象粒度**的差别：

| 对象粒度 | 例 | 为何看起来"单值/多值" |
|---|---|---|
| **项目主体** | 工期、金额、开工日期、建设规模 | 对象只有一个（项目主体）→ 表现为**单值** |
| **工程对象** | 垫层厚度、强度等级、管径、型号、配比、做法 | 对象有多个（基础垫层/地坪垫层/管道垫层…）→ 表现为**多值**，但**每个对象各自唯一** |
| **规范/通用** | 规范编号、阈值、龄期、频次、留置组数 | 对象是"规范/通用做法"→ **不作为项目实参**：可用于定性表述，禁止写成项目具体值、禁止当权威改写 |
| **噪声残片** | 条款号、`2.1招标`、图签 | 无归属 → **出局**（噪声闸已覆盖） |

> **由此，"单值型出现多值"不是一类情况，而是缺陷信号**：说明某个值被**误归**到了项目主体
> （实测：`材料投入计划 = DN1000`——DN1000 的对象是"室外排水管"），或属性名是从正文拼出来的假名。
> 处置是**定位误归并剔除**，不是"裁决选一个"。

## 1. 问题本质：一条统一的解释

资料里的事实**本来就是绑定的**——是我们把它拆散的：

| 资料原文（实测） | 它自带的结构 | 现在的处理 | 后果 |
|---|---|---|---|
| 清单特征描述：`1．部位：D4，有水房间 2．结合层厚度、砂浆配合比…30厚Ds M20干硬水泥砂浆 3．面层材料…防滑地砖600×600×10 4．基层做法：涂1.5mm厚JS-Ⅱ型聚合物水泥防水涂料` | **部位 + 逐项属性**:值（资料自带的结构化绑定） | 抽成 `精确参数 = 1.5mm`（对象、属性全丢） | 正文 4 个不同槽位都写成 1.5mm（垫层／虚铺／清底／隔热条） |
| 图纸标注：`1.75m/s ，基坑深度 -1.7 米（余同）` | `属性:值` 相邻成对 | 「本行绝对值最大者」取到流速 1.75 | 真值层工期/危大判定被污染（1.75m、24m） |
| 清单：`PHC400-AB95 / 混凝土强度等级：C80` | 同一条目里**型号与强度等级分列** | `C\d{2,3}` 在 `PHC400` 里抠出 `C400` | 定点修复器把正确的 **C80 改写成非法的 C400** |
| 图纸：`塘渣层计算弯沉值为3.41mm,压实标准见垫层压实度要求` | 弯沉值 ≠ 层厚 | 按"层名「垫层」+ 邻近 mm 数值"绑定 | 正文全部垫层厚度（含正确的 100mm）被改成 3.41mm→1.5mm |

**结论**：在"扁平值"上做的任何补救（无论检测还是改写）都必然错——因为它丢失了判断对错所需的**对象**。
唯一的根治方向是**保真绑定**；而一旦绑定保真，**写作与校验都变成"对照"而不是"猜"**。

## 2. 设计原则（5 条）

1. **绑定优先于猜测**：凡参与写作/校验/改写的值，必须携带对象与来源；绑定**只能来自原文共现**；抽取不到对象的值按**缺陷**处理（有锚点必须抽到，无锚点即残片），不设「用不上」这类中间态。
2. **唯一性粒度是 `(对象, 属性)`**：不是属性名。同一对象同一属性多值 = 缺陷信号（误归/抽取不全），定位并报出，**不裁决、不选值**；不同对象各自有值才是正常的"多值"。
3. **权威必须自证**：来源可溯 + 形态合法 + 对象唯一 + 属性自洽，四者齐备才算权威；四者不齐**既不报也不改**。
4. **改了就对**：只有权威自证的项才允许机器改写，且**改完必须回读验证**（同源检测器判定通过）。
5. **报告即证据**：每条报告都带对象/现写值/权威值/来源原文/处置，人可逐条自查（不做无法自证的告警）。

## 3. 方案

### 3.1 第 1 层：绑定事实层（BoundFact）——抽取期保真

**统一结构**：
```
BoundFact = {
  object:      '基础碎石垫层' | '块料地面/D4' | '项目'      // 对象（部位/条目/构件/层位/项目主体）
  attribute:   '厚度' | '结合层厚度' | '混凝土强度等级' | '基层做法'
  value:       '100' | 'C15' | '涂1.5mm厚JS-Ⅱ型聚合物水泥防水涂料'
  unit:        'mm' | '' 
  shape:       'measure' | 'grade' | 'spec-token' | 'prose'  // 形态（决定合法性判据）
  source:      { file, 原文片段, offset, section }
  binding:     'explicit' | 'inferred'                       // 绑定强度（显式/推断）
}
```

**三个抽取来源如何拿到对象（全部用资料自带结构，不猜）**：

| 来源 | 对象从哪来 | 属性从哪来 |
|---|---|---|
| **清单特征描述**（最富矿） | 「**1．部位：X**」子项 → 定义对象；其后所有子项归属该对象。清单条目名（`BoqEntry.name`）作对象名 | 各子项标签（「2．结合层厚度、砂浆配合比」→ 属性=结合层厚度；「4．基层做法」→ 属性=做法） |
| **图纸标注** | 属性名即对象（基坑深度）；同图区域/图名可作对象前缀（如「2#门卫结构图 / 基础」） | 标注标签（坡底线/坑底标高/开挖深度…），**且值必须与标签直接相邻** |
| **项目级声明** | 对象=项目主体（本工程/本项目） | 显式标签（计划工期/最高投标限价/开工日期…） |

**关键动作（第一批落地）**：
- `splitFeatureSegments` 扩为 **`parseBillItemSegments`**：识别「部位」子项，输出 `{ object, attribute, value }[]`。
- **裸值不是"出局"，而是"重绑定"**（实测数据推翻了一刀切：参数池 360 条里"无对象"的 132 条
  ——36.7%——**几乎全是有意义的值**：`241.7平方米`=2#门卫面积、`13.5平方米`=3#门卫面积、
  `PHC400-AB95`=管桩型号、`2026年`=业绩年份；只有 12 条（3.3%）是真残片）：

  **绑定只有一个合法来源：原文中「对象」与「值」的共现。** 其余一切推断都不算绑定。

  | 步骤 | 做法 |
  |---|---|
  | ① 抽取期同时抽对象（**主线**） | 对象必须在抽取的那一刻就从原文取出，**不允许事后补**：<br>· 清单特征描述的「1．部位：X」子项结构（资料自带）<br>· 图纸/说明句中与该值**最近的限定主语**（同句或紧邻上一句，带限定关系）<br>· 表格里的**行首词/列头**（对象在表格结构里）<br>· `extractPreciseFactsFromEvidence` **已经取了 ±40 字上下文却直接丢弃**——至少先把这段上下文用起来（`1#厂房建筑面积72062.84平方米` → 对象=1#厂房） |
  | ② 值的归属**只有二态，且穷尽**（不存在"暂时用不上"） | **有对象锚点（同子项/同行/同句主语）→ 必须抽到**；抽不到即**抽取器缺陷**，构建期报出 + 计入「**解析覆盖率**」（目标 100%，逐条给原文位置），按 bug 修，**不设"暂时"**。<br>**确实无锚点 → 它不是"值"而是残片**（噪声）→ 出局（现有噪声闸）。<br>⇒ 「用不上的值」的正确数量是 **0**；不为 0 就是缺陷工单的一行 |
  | ③ 归属域归一 | 归不到工程对象的，按 §0 表判归属域：项目主体级 → 单值型；规范通用级 → 标注规范口径 |
  | ④ 真噪声出局 | 残片/拼接标签/复写（实测 12 条）→ 出局（噪声闸已覆盖） |

- **为什么不做「值反查对象」（曾写过，已删除）**：实测**值→对象是重度多对多**——`C15` 出现在
  1,089 个资料块、`100mm` 110 个、`1.5mm` 82 个。反查要么恒为多义（等于什么也没做），
  要么在碰巧唯一时**凭空造出一个资料并未给出的绑定**——那等于把"猜"包装成"验证过的权威"，
  正是本方案要根治的错误。抽取不到对象，正确的反应是**补抽取**，不是兜底推断。
- **"对象锚点"是客观存在的**（实测：池中显示"无对象"的值 100% 都在原文里带锚点）：
  `241.7平方米`←「本工程**门卫**地上建筑面积 241.71 平方米」、`71807.64平方米`←「本工程**厂房**地上建筑面积…」、
  `PHC400-AB95`←「**桩**采用PHC400-AB95」、`4145.74`←清单行「**墙面涂膜防水** … | 4145.740 | m2」。
  三类锚点形态：**清单结构化子项（部位）／表格行首-列头／说明句主语**——抽取器覆盖这三类即达 100%。
- **共现校验（入闸，非补绑手段）**：`(对象, 属性, 值)` 三者必须在原文中共现（限定窗口 + 明确关系词）。
  `DN1000` 与「材料投入计划」原文从不同现 → 值对不成立 → 剔除。这一条直接消掉 A 组 25 条误归。
- 图纸深度取值：改为「**属性标签与值必须相邻**」+ 非厚度语义排除（本轮已做的 4 道闸并入此层，不再散落）。

**预期效果**：参数池从"360 条扁平值"变成"绑定事实"——`1.5mm` 只出现在
`(块料地面/D4, 基层做法, 涂1.5mm厚JS-Ⅱ…防水涂料)` 这一个位置，**模型想移植都没有可移植的裸值**；
而 `241.7平方米` 会以 `(2#门卫, 建筑面积, 241.7平方米)` 的形态出现，不再与 1#厂房的 72062.84㎡ 混在一个键里。

### 3.2 第 2 层：属性分型——多值合法性的判据

**判据（机制自证，不预设字段白名单）**：不再"按属性名分型"，而是**按对象与值的共现证据**判定：

```
同一 (对象, 属性) 对：
  ├─ 值唯一                              → 正常（无论对象是项目主体还是具体部位）
  ├─ 值多个 且 对象 = 项目主体            → 缺陷信号：至少一个值是**误归**（或属性名是拼接假名）
  │                                         → 定位误归（共现校验）并剔除，不裁决
  ├─ 值多个 且 对象 = 具体部位            → 缺陷信号：该对象该属性抽取不全 → 标「未定」，不选值
  └─ 对象 or 属性 为空 / 为拼接假名       → 剔除（不入权威、不写入）
```

> 注意：**多值型的"多值"指的是"多个不同对象各有一个值"**，落在铁律下并不冲突；
> 只有"同一对象同一属性多个值"才是缺陷。

**用途（三处同时生效）**：

| 消费方 | 现在的行为 | 改为 |
|---|---|---|
| 检测器（`processSpecConflictIssues`/`caliber-consistency`） | 对「垫层 有多个厚度」报"口径冲突" | **多值型不报**（本就该多值）；只报"同一对象同一属性出现越界值" |
| 定点修复器（`fixChapterDeterministic` 等） | 把多值型"归一"到唯一值 | **多值型永不归一**；只有单值型（且权威自证）才改写 |
| 写作注入 | 扁平值清单 | 多值型**逐对象列出**（见 3.3） |

### 3.3 第 3 层：对象化注入 + 按章分配（"分配也要对"）

**注入形态（替换现有 `- 键（字段名）：值`）**：

```
【本章对象参数清单（逐对象写实；值不得跨对象借用；同一属性在不同对象下各有其值，并列合规）】
· 基础碎石垫层（部位：基础）｜厚度=100mm｜材料=C15混凝土｜做法=分层摊铺、碾压密实
· 地坪垫层（部位：1#厂房地坪）｜厚度=300mm｜材料=…
· 块料地面 / D4（有水房间）｜结合层厚度=30厚Ds M20干硬性水泥砂浆｜面层材料=防滑地砖600×600×10｜基层做法=涂1.5mm厚JS-Ⅱ型聚合物水泥防水涂料
```

**分配算法**（复用现有成熟通道，不另造）：
1. 对象 → 章节：用 `chapterDutyDeclaration` / `plannedSectionPlacement` / `assignStructureRequirementsToChapters`
   同一套匹配（对象名/部位名 ↔ 章主题/规划小节名），落成 `章 → 对象[]`。
2. 对象 → 小节：章内 H3/H4 小节名与对象名匹配（「基础工程」↔「基础碎石垫层」）。
3. **分配不上的对象**：不注入正文，进「分配缺口清单」（**不诱导写错**）。
4. 写作红线（与已发布的指向型禁令一脉）：
   - 不得写清单外的值；
   - 不得把某对象的参数写到另一对象；
   - 多对象多值**并列是合规的**，禁止"统一"或"取其一"。

**工艺/方法类**（你提到的"不同工艺或方法"）同样走绑定：清单「基层做法／施工方法」子项、
图纸设计说明的做法句 → `(对象, 做法, 文本)`；要求写手**按对象写该对象的做法**，不得跨对象套用。

### 3.4 第 4 层：权威验证链（"验证我们的规划是否正确"）

**构建期自检（生成之前，不是交付之后）**——对 BoundFact 层与蓝图/真值层跑四道校验：

| 校验 | 内容 | 不通过时 |
|---|---|---|
| **① 来源可溯** | 值能回指 资料文件 + 原文片段 + 偏移 | 剔除（不当权威、不入清单） |
| **② 形态合法** | 值域/形态闸（**统一到一处**）：强度等级 C15~C80；层厚 0.5~1000mm；配比分母 ≤100；管径 `DN\d+`；钢筋 `HRB/HPB\d{3}`；数值不得来自"偏差/弯沉/压实度/间距/标高"等异义槽；型号 token 不得字母紧邻（`PHC400` ≠ `C400`） | 剔除并记 `noiseRejected`（可审计） |
| **③ 属性自洽** | 属性名与值形态相容（文本型属性不得取裸型号值；多标签拼接的属性名非法；规格型属性不得取长句） | 剔除并记录 |
| **③b 三者共现**（新增） | `(对象, 属性, 值)` 必须在原文中**共现**（限定窗口 + 明确关系词）；否则是误归 | 剔除并记录（`材料投入计划=DN1000` 即此类） |
| **④ 规划自检** | ① 每个 `(对象, 属性)` 对**值唯一**（唯一铁律；变更链除外）；<br>② 对象为"项目主体"的属性若出现多值 → **误归**：定位来源并剔除，**不裁决**；<br>③ 对象为具体部位的属性若同一对多值 → 报"该对象该属性未定"（抽取不全），**不选值**；<br>④ 每个 BoundFact 的 object 非空、非标签拼接、非残片 | **构建期报错**（宁停不猜） |

**运行期回读自检（写作之后）**：正文中每个对象的属性值必须 ∈ 该对象的权威集合；
出现集合外值 → 报「越界值」（**报的是"正文写了不在权威集合里的值"，不是"与某唯一权威不符"**）。
→ 这是唯一能同时支撑"多值型正确"与"可验证"的判据形态。

### 3.5 第 5 层：改写与报告的最终口径（回应你的两条纠正）

```
权威通过四道校验？
 ├─ 通过（可自证） → 确定性改写该对象处的越界值 → 改完回读验证（同源检测器必须清零）
 │                    → 报告：「已按 <资料名·原文片段> 将 <对象> 的 <属性> 由 X 改为 Y」
 └─ 未通过（不可自证） → 既不报、也不改（只进 diagnostics 观测指标，不进人工清单、不阻断）
```

- **不再是「只报不改」**：能自证的一律改对；不能自证的一律不出现在报告里（不制造无人能修的 blocker）。
- **报告即证据**：每条含 对象/现写值/权威值/来源原文/处置，评标人可逐条复核。
- 人工清单只收敛「能自证但自动轮次未修好」的项。

## 6. 风险与明确不做

**风险**
1. **参数注入量下降**（裸值出清）→ 可能影响"参数落位率/参数密度"类指标与评分口径 → **需同步调整指标定义**（改口径而非放宽）。
2. **对象识别不全**（清单特征描述形态多样）→ 漏绑的值出局（宁可少写不可写错）；用"分配缺口清单"暴露，逐步补抽取。
3. **单值型自检报错**（构建期停下）→ 生成成功率短期下降；换取"不猜"。

**明确不做**
- 不再用"提取到的唯一值"当权威；
- 不对多值型做任何"统一/归一/取众数"；
- 不放宽任何阈值让分好看；
- 不为未证实的问题先动代码。
