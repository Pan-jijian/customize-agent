# 4.60 重心倒置：审查与方案

> 用户判断（2026-09-24）：
> *「只要我们召回的数据质量够高够好够全、一体化规划蓝图够准确够合理，写作的时候很好，
> 那么无论是检测器还是修复器，根本就不需要作为主力军去完成文档。」*
>
> **本方案的任务：用实测数据审查这个判断，并给出把重心倒置过来的完整路线。**

---

## 一、结论先行

**判断成立。** 而且本轮实测给出了三条直接证据——**下游（检测/修复）承担了本不该由它承担的产出量，
而上游（规划）给出的目标本身就不可执行**。

| 证据 | 数据 | 含义 |
|---|---|---|
| **写作一次通过率** | 第一章 42 个块耗 **84 次**写作调用 | 约 **50%** 的块一次过不了，写作调用翻倍 |
| **块失败原因构成** | 55 次质检不达标中 **46 次是篇幅（83.6%）** | 首要失败原因**不是内容质量，是字数** |
| **块目标可执行性** | 块目标 1020 字 → 实际产出 **549 / 682 / 1183 / 1459 / 1700 / 1713**（0.54×~1.68×） | **同一目标产出跨 3 倍**——目标本身不可执行 |

**关键推论**：46 次篇幅失败 → 46 次重试 → 块反复 → 章结构抖动 → 检测器报出 → 修复器收敛。
**下游的活，绝大部分是从"上游给了一个不可执行的目标"派生出来的。**

### 必须同时纠正的一个说法

用户此前提「大部分内容是在修复链中补充的」。**本轮**数据**不能**支持也不能否定它——
因为**写作期快照被覆盖**（`checkpointChapters` 与终稿等长），**内容归属测不出来**。
反而可见的是：修复轮 LLM 调用 32 次（13.0%），**不是**调用量主力。

**这个"测不出来"本身是审计的第一缺口**（见 §3 I1）。

---

## 二、审查：三层上游各自的问题（全部为本轮实测）

### 2.1 召回层

| 观测 | 数据 |
|---|---|
| 证据上下文规模 | **3,248,417 字** / 41 份文件 / 检索 85 次 |
| 未标注调用（judge 类） | 55 次，其中 **schema 失败 9 次** |
| 参数落位 | **19/34**（漏 15 项） |
| 无主数值 | 缺口 2~5 处（逐轮波动） |

**问题**：召回量极大（324 万字进上下文），但**落位率低**（参数 19/34）且**无主数值仍在**。
即「召回了但没有被用上」与「没召回但正文出现了」并存。
**缺一个度量：召回利用率（召回条目中被正文实际引用的比例）与召回信噪比。**

### 2.2 蓝图/规划层（**本轮定位到的最大问题源**）

| 观测 | 数据 |
|---|---|
| 块目标可执行性 | 目标 1020 字 → 产出 549~1713（**跨 3 倍**） |
| 章规划小节数 | 第一章 **42 个** |
| 装配层结构 | 把草稿的「H3 父 + H4 子」展开为**同级 H3** → 父标题被掏空（A2 根因，8 个真实文档 100% 复现） |
| 分项方案要素 | 6 个分项被判要素不全（C1 已修判据侧） |

**问题**：块预算**没有以模型的实际产出分布为基准**。容量规划给出 1020 字，
而模型对 1020 的产出天然落在 549~1713 —— 于是**每次生成都必然有大量块越线**，
这不是写作能力问题，是目标不可执行。

### 2.3 写作层

| 观测 | 数据 |
|---|---|
| 一次通过率 | ~50%（42 块 / 84 次调用） |
| 失败原因 | 篇幅 46、归因量化 7、清单外标题 3、结构 2 |
| 篇幅接受区放行 | 53 次（首轮欠产但末轮放行的量） |
| 耗时 | phase:draft **485.9 秒**（占三段 78%） |

**问题**：写作把**大部分算力花在"对不上目标"的返工上**，而不是写内容。
去掉篇幅返工，写作调用可省约 **46/118 ≈ 39%**。

### 2.4 下游（检测/修复）——规模与占比

| 观测 | 数据 |
|---|---|
| 检测器 | **158 个** |
| 修复轮 | **35 轮** |
| 修复 LLM 调用占比 | **13.0%**（32/247） |
| 质量发现 | 221 条（阻断 50 / 重要 123 / 轻微 48） |
| 终检才发现的比例 | **96.7%**（4.58 实测 30 条阻断中 29 条） |

**问题不在"下游调用多"，而在"下游是唯一发现问题的地方"**（96.7%）。
即：**写作期没有自检能力，所有判据都堆到了链尾**。

## 三、方案：把重心倒置过来

### 核心理念

```
现状：  上游给不可执行的目标 → 写作返工 → 下游发现并兜底
目标：  上游给可执行的目标   → 写作一次做对 → 下游只做安全网
```

**度量随之倒置**：

| | 现行主指标（都是下游度量） | 目标主指标（上游度量） |
|---|---|---|
| 1 | 阻断数 | **写作一次通过率**（当前 ~50% → 目标 ≥90%） |
| 2 | 交付置信度 | **修复链净增字数占比**（当前不可测 → ≤5%） |
| 3 | — | **召回利用率**（召回条目被正文引用比例） |
| 4 | — | **块目标命中率**（产出落在目标带内的块占比） |

### I1｜度量先行（**必须先做，否则全是盲改**）

| 编号 | 内容 |
|---|---|
| I1-1 | **内容归属插桩**：写作期产出字数 / 每轮修复净增（新增+改写分开） / 块丢弃清单 / 结构差，随 `executionStages` 落盘 |
| I1-2 | **写作一次通过率**按块统计（首轮通过 / 重试后通过 / 放弃），落到诊断 |
| I1-3 | **召回利用率**：召回条目 → 正文引用率（可按事实池条目对正文做包含/语义命中统计） |
| I1-4 | 把上述三项接入 `document-diagnostics` 阶段与质量报告 |

### I2｜规划可行性（**收益最大的单点**）

| 编号 | 内容 |
|---|---|
| I2-1 | **块目标以模型产出分布校准**：用真实归档回归「块目标 → 实际产出」的分布（已有 8+ 份产物），定出**可执行带**而非点值 |
| I2-2 | **容量规划改为区间下达**：块目标给区间（如 1020 字 → `[0.7×, 1.4×]`），且区间以 I2-1 的分布为基准 |
| I2-3 | **块粒度复核**：第一章 42 个规划小节 → 是否块过细导致目标碎片化？以「每块可承载的实质内容量」评估 |
| I2-4 | 蓝图校验增加**可执行性检查**（目标与模型产出分布兼容性），不兼容即在校验期报出，而不是留给写作期去撞 |

### I3｜写作一次做对

| 编号 | 内容 |
|---|---|
| I3-1 | **篇幅返工消除**：I2 落地后，块级篇幅失败应从 46 降至个位数（这是本项的直接判据） |
| I3-2 | **写作期自检前移**：把「检测器三态」中判为 `self-check` 的族（P0 门已声明 44 项）真正接线到块成稿后——**当前它们仍是链尾发现** |
| I3-3 | 写作任务卡与判据**逐项同源**（P2 已做，但需确认走的是活跃通道——**本批已纠正一处死路径接线**） |

### I4｜召回质量

| 编号 | 内容 |
|---|---|
| I4-1 | **信噪比度量**：324 万字证据上下文中，被正文引用的比例 |
| I4-2 | **参数落位 19/34 → ≥90%**：漏 15 项的成因分类（召回未给 / 给了但写作未用 / 用了但被判无主） |
| I4-3 | 无主数值：区分「真编造」与「有源但溯源链断」——前者拦、后者补溯源 |

### I5｜下游降级为安全网

| 编号 | 内容 |
|---|---|
| I5-1 | **修复轮处理量阈值化**：任何族在修复链中的处理量占比 >5% 即为「上游未做对」的信号，进审计而非默认接受 |
| I5-2 | **terminal-only 收敛**：P0 门已登记 27 项只能终检的检测器，逐版本下降 |
| I5-3 | 158 个检测器中，**未被写作期约束覆盖**的部分逐项接线（P0 门已把 84 项声明为 `constraint`，需验证是否真的到达写手——**本批已发现一处声明了却没到达的死路径**） |

### I6｜装配层根因（A2 治本）

| 编号 | 内容 |
|---|---|
| I6-1 | A2 已**治标**（链尾清除空壳标题，真实归档 16 → 0）；**治本**需定位装配层「把 H3 父 + H4 子展开为同级 H3」的单点并修正语义（父标题应保留其子节，不应被掏空） |
| I6-2 | `pipelineInvariants` 的 INV-2（层级提升边界，当前 171 项违反）作为验收口径 |

## 四、路线与判据

| 期 | 内容 | 判据 |
|---|---|---|
| **P0** | I1 度量插桩 | 每轮记录含：写作期字数、各轮净增/改写、块丢弃、一次通过率、召回利用率 |
| **P1** | I2-1/I2-2 块目标区间化（用真实产物回归校准） | **块目标命中率 ≥80%**；块级篇幅失败从 46 → ≤5 |
| **P2** | I3-2 写作期自检前移（按 P0 门已声明的 self-check 族） | 终检才发现的问题占比 **96.7% → ≤50%** |
| **P3** | I4 召回质量 | 参数落位 **19/34 → ≥90%**；召回利用率可视 |
| **P4** | I5 下游阈值化 | 修复链净增占比 ≤5%；terminal-only 逐版本下降 |
| **P5** | I6 装配层治本 | INV-2 违反 → 0 |

**贯穿的硬指标**（每轮真实生成都量）：

1. **写作一次通过率** ≥90%（当前 ~50%）
2. **块目标命中率** ≥80%（当前不可测，样本显示 549~1713 vs 目标 1020）
3. **修复链净增字数占比** ≤5%（当前不可测）
4. **终检才发现的问题占比** ≤50%（当前 96.7%）
5. **召回利用率**（新指标，先建基线）

## 五、必须同时做的验证方式（用户 2026-09-24 指令）

本仓教训：**单模块单测测不出跨模块矛盾**——8 个真实文档 100% 复现的 A2，三个空节判据各自都有单测、都绿。

故本方案的所有改动，一律按三层验证：

| 层 | 手段 | 已有基础设施 |
|---|---|---|
| **单元矩阵** | 每族 ≥10 例：正向/反向/边界/不变，文本逐字取自真实缺陷 | 本批已建（R-A1 14 例、A2 14 例、B5 69 例等） |
| **流水线一致性** | 跨判据不变量，跑在真实归档上 | `pipelineInvariants.manual.ts`（INV-1~4 + A2 回放） |
| **真实业务回放** | 用**本地知识库真实产物**驱动，断言可达目标状态**且修复前确实违反**（防测空气） | 同上（A2 回放：16 → 0） |

## 六、风险

| 风险 | 缓解 |
|---|---|
| I2 改块目标区间 → 章预算守恒被破坏 | 章预算账（4.56 2-b）已在管章级守恒；区间只改块级下达形态，Σ 守恒不变 |
| I1 插桩改动管线 | 只增记录、不改行为；插桩失败不阻断生成 |
| 度量倒置后历史分数不可比 | 新旧指标并行一个版本，历史快照不回改 |
| 「上游做对」的收益被高估 | P1 用真实产物回归校准，不靠推断；判据是块目标命中率而非主观感受 |
| 召回利用率低被误读为召回无用 | I4-2 先做**成因分类**（未给/未用/被误判），分类后再定处置 |
