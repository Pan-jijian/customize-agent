## 0. 你的判断与我的结论

你说的：**「写的时候是对的，是修改/一致性修复把值改错了」**——实测支持这个判断：

> 当时模型写的 `基础下做100厚碎石垫层`（图纸原件就是 `100厚碎石垫层`）**是对的**，
> 是**确定性定点修复器**把它改成 `3.41mm`，下一环节又改成 `1.5mm`。
> 而 `3.41mm` 的来源是源资料里一句 **`塘渣层计算弯沉值为3.41mm`**——**弯沉值被当成了层厚度**。

**结论**：当"权威"来自**提取推断**时，机器改写**改错 > 不改**。检测器该留（它们是对的），
"确定性改写"该退场。

## 2. 根因：两层不可靠叠加

1. **权威提取会错**：`C\d{2,3}` 在 `PHC400-AB95` 里抠出 `C400`；层名「垫层」把**弯沉值**当厚度；
   层名粒度太粗（「垫层」不是单一对象：基础垫层 100mm／管道垫层 10cm／地坪垫层 300mm 都叫垫层）。
2. **"唯一即权威"不成立**：资料里"唯一"往往只是**没抽到别的**，不等于口径唯一；
   而代码把"提取到的唯一值"当成了"权威"，于是从「宁缺毋假」滑成「机器盲改写」。

> **代码自身的原则早就写对了**（`integrity/fixers/fixers.ts` 注释）：
> 「多值冲突时无权威可依不修复——由检测器阻断 + LLM 定向修复裁决（**机器不得在多套口径中盲选一套写入，宁缺毋假**）」
> 缺的只是把"提取到的唯一值"也纳入"无权威"的范畴。

## 4. 影响（必须让你先看到）

**代码影响**：已实现，未提交。开关关闭后有 **21 个旧测试失败**——它们断言的正是被取消的改写行为
（`numericConflictArbiter` 7、`dicCoverageGapBoundary` 5、`documentIntegrityChecks` 2、
`qualityValidation` 1、其余 6）。需要把这些测试改成新契约（只报不改），并保留其场景。

**产品影响**：

| 维度 | 影响 |
|---|---|
| 正文正确性 | ⬆️ **提高**：不再有"把正确值改错"的静默损坏（本轮 ≥12 处） |
| 阻断项数量 | ⬆️ 增加：原先被"改写掉"的冲突会留在检测报告里 → 进人工清单（例：垫层规格冲突从"静默改掉"变成"报出"） |
| 交付外观 | 正文保留写手/资料的正确值；冲突以清单形式可追溯，而不是被机器悄悄统一 |
| 依赖度 | 不再依赖"清单/资料抽取永远正确"这个不成立的前提 |

**风险**：原先靠确定性改写"清零"的冲突会残留（进人工清单）。历史上这些改写是为了打破
「残留冲突 → 导出门禁阻断 → 继续生成死循环」而加的——需确认：**人工清单不阻断导出**（当前口径如此，63 项阻断照常导出），
故不会死循环。
